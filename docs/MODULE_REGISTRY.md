# Реестр модулей: почему меню собирается само

## Проблема, из-за которой это написано

В системе 99 работающих страниц под `/UNA.md/orasldev/`. В меню портала
их было **пять** — список был вписан руками в шаблон `sqldeveloper_mdi.html`,
и каждый, кто добавлял модуль, должен был про этот шаблон вспомнить.

Не вспоминали. Biro26 (38 страниц), Планограммы, ServOuts26, Colass,
Nufărul и DECOR существовали, работали, были задокументированы — и были
невидимы из портала. Найти их можно было только по прямой ссылке,
то есть если ты уже знаешь, что они есть.

Отдельно то же самое повторялось в документации: реестр `PLG_DOCS` жил
в `app.py`, и новый `.md` в папке не появлялся в хабе, пока кто-нибудь
не допишет строку.

Причина у обеих болезней одна: **список, который надо не забыть обновить.**
Пока проект пишет один человек, это работает. Как только над ним работают
несколько сессий и несколько людей — перестаёт.

## Решение: источник правды — не список, а факт

Три уровня, и все три работают без ручного действия.

### 1. Модули портала — по карте маршрутов Flask

`models/module_registry.py` при первом обращении к меню проходит по
`app.url_map` и собирает все GET-страницы под `/UNA.md/orasldev/` без
параметров и без `/api/`. Группирует по первому сегменту адреса:
`biro26-site/account`, `biro26-admin` и `biro26` — один модуль `biro26`.

Если маршрут зарегистрирован — он в меню. Никакой регистрации «ещё
и в списке» не требуется, забыть нечего.

### 2. Манифест — только оформление

`modules/<ключ>/module.json`:

```json
{
  "title": {"ru": "Планограммы и автозаказ",
            "ro": "Planograme și comandă automată",
            "en": "Planograms & auto-order"},
  "icon": "▦",
  "order": 10,
  "url": "/UNA.md/orasldev/planograms",
  "docs": "docs/Planograms",
  "sql_prefix": "PLG_, PECO_",
  "descr": "Выкладка, прогноз заказов, фреш, импорт, топливо, ИИ-мониторинг",
  "pages": {"planograms/docs": "Документация модуля"}
}
```

Манифест даёт человеческое название, иконку, порядок и подписи страниц.
**Спрятать модуль манифестом нельзя** — это принципиальное ограничение,
а не недоделка: возможность скрыть вернула бы ровно ту болезнь, ради
которой всё написано. Модуль без манифеста виден с названием из адреса
и пометкой «без манифеста».

Обратная ситуация — манифест есть, а маршруты не отвечают — тоже видна:
такой модуль показывается красной карточкой. Это сигнал, что что-то
отвалилось, а не повод молча убрать пункт.

### 3. Документация — по содержимому папки

`models/doc_registry.py` читает `docs/<Модуль>/*.md`. Файл `docs.json`
рядом задаёт заголовок, аудиторию, иконку, порядок и флаг `public`.
Документ без записи в манифесте всё равно в хабе: заголовок берётся
из первого `#`, описание — из первого абзаца.

**Публичность по умолчанию — нет.** В docs-папках лежат пути на сервере,
размещение wallet и перечень ключей окружения. «Видно в хабе» и «читается
без входа» — разные вещи: первое верно всегда, второе — только когда
в `docs.json` стоит `"public": true`.

### 4. Разделы внутри SPA-модуля

В модуле «Планограммы» разделы — это панели `<section class="panel"
id="panel-xyz">`, а меню строится из массива `NAV`. Функция
`syncNavWithPanels()` сверяет одно с другим перед каждой отрисовкой
и дописывает недостающие пункты: подпись из словаря по ключу `nav.<id>`,
а если и его нет — из идентификатора. Такой пункт помечен точкой вместо
иконки: «раздел найден, но ему не назначили ни иконку, ни перевод».

## Где это смотреть

| Что | Адрес |
|---|---|
| Карта системы: все модули и страницы | `/UNA.md/orasldev/modules` |
| То же в JSON (для проверок деплоя) | `/api/modules` |
| Пересканировать без перезапуска | `/UNA.md/orasldev/modules?refresh=1` |

## Что делать автору нового модуля

1. Написать маршруты под `/UNA.md/orasldev/<имя>` — этого уже достаточно,
   чтобы модуль появился в меню.
2. Создать `modules/<ключ>/module.json`, чтобы он там выглядел прилично.
3. Положить документацию в `docs/<Модуль>/` и описать её в `docs.json`.
4. Проверить: `/UNA.md/orasldev/modules` — модуль на месте, рамка не красная
   и не оранжевая.

Чего делать **не надо**: править шаблон меню. Если пункт понадобилось
вписать руками — сломалось автообнаружение, и чинить надо его.

## Проверка после деплоя

```bash
curl -s -b "session=<cookie>" https://nufarul.eminescu.md/api/modules \
  | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['total_modules'],'модулей',d['total_pages'],'страниц',d['without_manifest'])"
```

Если число страниц упало после релиза — маршруты не поднялись,
и это видно сразу, а не через месяц.
