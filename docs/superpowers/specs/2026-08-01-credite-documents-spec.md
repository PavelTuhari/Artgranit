# Кредитные заявки как документы ERP + master-detail в бэк-офисе

**Дата:** 2026-08-01 · **Статус:** решения приняты владельцем, этапы 2–4 не начаты

## Решения владельца (2026-08-01)

1. **`NRSET = 201` у всех документов, приходящих с сайта.** Это не ключ, а значение
   управленческого слоя: **201 — управленческий учёт**, **301 — бухгалтерский**.
   Кредитный документ получает тот же `NRSET = 201`.
2. **Объектные типы не использовать.** `TMDB_ST201M/D` хранят `DT`/`CT` типа `UN$CM`
   (объект с `.CONT`, `.SC`, `.DEP`, `.SUMA.DEF`, `.CANT`) — это бухгалтерские проводки.
   Для кредитов делаем **обычные плоские колонки**, как в прочих `TMDB_*` таблицах.
3. **Пакет — отдельный: `y_ai_BIRO26_credite`.** Не расширять `y_ai_BIRO26`.
   Документы счетов создаются через `y_ai_BIRO26.create_invoice()` / `add_line()`;
   кредитные — через новый пакет, тем же принципом.

## Как устроен существующий контур (выяснено при обследовании)

- `TMDB_DOCS` — реестр документов: `COD` (PK), `TIP`, `TIPDOC`, `DATAMANUAL`,
  `NRMANUAL`, `NRSET`, `STATUS`, `DIV`, `CODF` и др.
- `TMDB_ST201M` — шапка (1:1 к документу, `COD` = `TMDB_DOCS.COD`).
- `TMDB_ST201D` — строки (`COD` + `COD1` = номер строки).
- `VMDB_ST201M` / `VMDB_ST201D` — вью, разворачивающие объектные поля в плоские.
- Документы **не вставляются напрямую** — только через PL/SQL-пакет.

## Что делать (этапы)

### Этап 1 — выгрузка гридов в Excel на уровне ядра ✅ СДЕЛАНО

Общий помощник `static/biro26/grid-export.js`, подключается ко всем гридам бэк-офиса.
Формат — SpreadsheetML (открывается Excel), без внешних библиотек и CDN.

### Этап 2 — страницы Easy Credit и Libercard

Отдельные страницы бэк-офиса с полями заявки: **NNP, IDNP / IDNO, номер контакта,
адрес домициля / юридический**. Поля уже собираются формой в корзине
(`ec-fio`, `ec-idnp`, `ec-phone`, `cr-address`) и сохраняются в `TMS_CREDITE_REQ`
(включая `CLIENT_ADDRESS`).

### Этап 3 — таблицы, вью и пакет

- `TMDB_CREDITE_M` — шапка кредитного документа: `COD` (= `TMDB_DOCS.COD`),
  **`DOC_COD_ORDER`** — ссылка на `TMDB_DOCS.COD` заказа/счёта (главное требование),
  клиент, ФИО, IDNP, телефон, адрес, организация кредитования, пакет, срок, аванс,
  сумма, цена в рассрочку, статус в банке, `EXT_REF` (URN).
- `TMDB_CREDITE_D` — строки: `COD` + `COD1`, товар, количество, цена, сумма.
- `VMDB_CREDITE_M` / `VMDB_CREDITE_D` — вью поверх них, по образцу `VMDB_ST201*`
  (но без разворачивания объектов — колонки уже плоские).
- Пакет `y_ai_BIRO26_credite`: `create_credit(...)`, `add_line(...)`, `last_doc`.
- DDL и пакет ставятся отдельным идемпотентным скриптом, как
  `deploy_credite_oracle.py`; в обычный `deploy_to_remote.sh` DDL не входит.

### Этап 4 — вкладка master-detail + Google Sheets

- Вкладка в веб-админке: грид шапок (master) + грид строк (detail).
- Кнопка выгрузки в Excel — из этапа 1.
- Синхронизация с Google Sheets: настройка в бэк-офисе. **Понадобится от владельца:**
  сервисный аккаунт Google (JSON-ключ) и ID таблицы.
