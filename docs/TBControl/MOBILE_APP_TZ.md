# ТЗ: мобильное приложение «TBControl Mobile» (iPhone)

**Версия:** 1.0, 02.09.2026. **Заказчик:** владелец сети Unisim.
**Реализация:** `ios/TBControlMobile/` (SwiftUI, iOS 17+, xcodegen).

## 1. Зачем

У владельца всё «хозяйство» размазано по нескольким системам: Zabbix 3.4
(серверы, сервисы, диски, теперь и температура CPU), TBControl (магазины,
кассы, события, инциденты), Telegram-бот на Blynk (t° и датчик движения).
Ночью 01.09 cloudbd грелся до 57–64℃, а заметно это было только по
мельтешению в чате. Нужен один экран на телефоне, который **сам привлекает
внимание**, когда:

1. **долго нет связи с Zabbix** (или с TBControl) — самое опасное состояние:
   молчащий мониторинг выглядит как «всё хорошо»;
2. температура CPU вышла за режим (>52℃ — повышена, ≥60℃ — перегрев);
3. пришла проблема уровня High/Disaster или сервер стал недоступен.

## 2. Источники данных

| Источник | Как | Доступ |
|---|---|---|
| **Zabbix 3.4** `http://192.168.0.110/zabbix/api_jsonrpc.php` | JSON-RPC: `user.login`, `trigger.get` (value=1, only_true), `item.get` (`cpu.temp[1|2]`, `system.uptime`), `host.get` (`available`) | только через VPN93 (L2TP) — приложение это учитывает: недоступность без VPN не считается аварией, если пользователь отметил «я вне VPN» |
| **TBControl** `https://nufarul.eminescu.md` | вход по хэш-инвайту `GET /UNA.md/orasldev/tbcontrol?h=<hash>` (cookie-сессия), далее `/api/tbc/stats`, `/api/tbc/events?status=open`, `/api/tbc/cassa`, `/api/tbc/sources` | из любой сети (HTTPS) |

Ключи и пароли хранятся в Keychain устройства. Инвайт для приложения заведён
в `INV_LINKS` (note «TBControl Mobile (iPhone)»).

## 3. Экраны

1. **Обзор** — две карточки связи (Zabbix / TBControl: состояние, «последний
   успешный опрос N мин назад»), плитки сети (магазины critical/degraded,
   устройства offline, события P1/P2), мини-датчики t° по серверам, топ
   проблем Zabbix.
2. **Температура** — по каждому серверу (cloudbd, PROXMOX3) два датчика
   CPU1/CPU2 с цветовыми зонами (зелёная <52, оранжевая 52–59, красная ≥60),
   история за сессию (спарклайн), uptime и доступность агента.
3. **Проблемы** — активные триггеры Zabbix, группировка по severity, возраст,
   хост. Локально можно «принять к сведению» (mute на 30 мин).
4. **Кассы** — магазины/кассы из Cassa Monitor: online/offline/shutdown.
5. **Настройки** — адреса, учётки, хэш-инвайт, пороги (t° warn/crit, минуты
   до «связь потеряна»), интервал опроса, тумблер «я вне VPN», тест сигнала.

## 4. Режим привлечения внимания (главное)

Три уровня, каждый громче предыдущего:

| Уровень | Когда | Что делает приложение |
|---|---|---|
| **Notice** (жёлтый) | связи нет 2–5 мин; t° 50–52 | полоса вверху экрана, бейдж |
| **Warning** (оранжевый) | связи с Zabbix нет > 5 мин (настраивается); t° > 52℃; проблема High | полоса + haptic «warning» + local notification (time-sensitive) |
| **Critical** (красный) | связи с Zabbix нет > 15 мин; t° ≥ 60℃; проблема Disaster; агент сервера недоступен | **полноэкранная красная заслонка** с пульсацией, звук + haptic «error» **повторяются каждые 20 с**, пока пользователь не нажмёт «Понял» (mute 30 мин); notification time-sensitive; бейдж на иконке |

Правила:
- «Связь потеряна» считается по **последнему успешному** опросу, а не по
  последней попытке — ошибка авторизации, таймаут и «нет сети» одинаково
  ведут к эскалации.
- Уведомления дедуплицируются по ключу (`link:zabbix`, `temp:cloudbd:1`,
  `trigger:<id>`), повторная отправка только при росте уровня или после
  окончания mute.
- В фоне: Background App Refresh (`BGAppRefreshTask`, id
  `md.una.tbcontrol.refresh`) — опрос + уведомления, если порог превышен.
- Пока приложение открыто — опрос каждые 30 с (настраивается).
- Восстановление связи/нормализация t° — зелёное уведомление «всё в норме»
  и снятие заслонки.

## 5. Нефункциональные требования

- iOS 17+, iPhone; ландшафт не требуется.
- Без внешних зависимостей (только Foundation/SwiftUI/UserNotifications/
  BackgroundTasks/AudioToolbox/Security).
- HTTP к 192.168.0.110 разрешён через `NSAllowsArbitraryLoads` (внутренняя
  сеть за VPN); TBControl — только HTTPS.
- Никаких секретов в исходниках: адреса по умолчанию есть, пароли и хэш вводит
  пользователь.
- Сборка: `xcodegen generate && xcodebuild -scheme TBControlMobile
  -destination 'platform=iOS Simulator,name=iPhone 17'`.

## 6. Приёмка

1. Выключить VPN → через 5 мин оранжевая полоса и уведомление, через 15 —
   красная заслонка со звуком, повторяется до «Понял».
2. Кнопка «Тест сигнала» в настройках воспроизводит critical-режим.
3. При t° cloudbd > 52 (ночью под нагрузкой это реально) — warning-уведомление
   с показанием; ≥60 — critical.
4. Обзор совпадает с `/api/tbc/stats` и `trigger.get` Zabbix.
5. После закрытия приложения фоновое обновление раз в ~15 мин приносит
   уведомления (частоту решает iOS).

## 7. Что не входит в 1.0

Push через сервер (APNs) — нет своего push-бэкенда; Critical Alerts Apple
(нужно отдельное entitlement от Apple); запись данных в TBControl (ack/
инциденты) — только чтение; Android.
