02Слепые зоны классического мониторинга

«Сервер доступен» ≠ «магазин продаёт»

Ping отвечает, а кассы не пробивают чеки: банк, фискализация, очередь синхронизации — вне поля зрения инфраструктурного мониторинга.

Данные теряются по дороге

Продажи идут цепочкой SQLite-касса → серверы магазина → центральный → бэк-офис. Застрявший батч виден только по жалобам бухгалтерии.

Версии ПО расползаются

Front Office 7.3.9 на одной кассе и 7.4.12 на соседней — обновления не проверяются, отставшие кассы никто не видит.

Контекст сбоя собирается вручную

Дежурный тратит час на сбор фактов. Внешние AI-ассистенты могли бы диагностировать мгновенно — им нужен полный структурированный контекст.

05Processing центр: путь данных от кассы до бэк-офиса

POS (SQLite) ──▶ Серверы магазина (1..N: MySQL/PostgreSQL/MSSQL/SQLite) ──▶ Центральный (Oracle) ──▶ Бэк-офис
     flow OK            flow LAGGING lag 95 мин · pending 8 900              flow FAIL: ORA-02291 batch rejected
  • Каждое звено — поток со статусом OK / LAGGING / STALLED / FAIL, отставанием и накопленным pending
  • Журнал батчей: отправлено/принято/ошибка; повтор передачи в один клик
  • Узлы: три уровня контроля — железо, приложение обмена, база данных (5 движков)

07Отчёт «Динамика»: инфраструктура + люди + бизнес

События по дням

P1–P4 stacked-бары за 7/14/30 дней — видно тренд деградации сети.

Очереди на кассах

Сломанный SCO → очередь 9 человек. Подсветка: «очереди растут — проверьте кассы/SCO».

Ненужные перезагрузки

Кассир 3 раза перезагрузил кассу при сбое банка — зафиксировано и посчитано. База для обучения персонала.

Обращения и время реакции

Техподдержка · банки · MEV (SFS) · электросети · ISP. Задержка 247 минут — красным.

Климат и питание

Жара +38° → серверная 34°, просадки до 198V, перегруз централи. Мороз −18° — тоже кейс.

UPS-телеметрия

Магазин на UPS: батарея 100→36%, остаток минут — решение «генератор или ждать» принимается по данным.

09AI-досье: сбой как документ для LLM

Что внутри MD-досье

  • ▸ контекст сбоя (событие / инцидент / поток)
  • ▸ паспорт устройства + метрики NOW + телеметрия 24ч
  • ▸ версии ПО, health checks, потоки и журнал батчей
  • ▸ STORE_HEALTH магазина и соседние события
  • ▸ инструкция AI: порядок диагностики + whitelist-действия

Доступ и безопасность

  • ▸ GET /api/tbc/ai/dossier/<code>.md?token=…
  • ▸ секретный токен на каждый документ, учёт прочтений
  • ▸ credentials в досье не включаются (Secret Store отдельно)
  • ▸ AI может: диагностика, retry потока, resolve, RCA
  • ▸ AI не может: финансовые данные, prod-конфиг, security
Автогенерация при каждом P1/P2-инциденте — внешний AI-провайдер получает полный контекст за секунды, а не за час ручного сбора.

10Источники событий: эмулятор и реальный Zabbix
