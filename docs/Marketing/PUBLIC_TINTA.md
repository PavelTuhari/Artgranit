# Целевые группы Artgranit: разработчики, Oracle, заказчики

*17.10.2026 · основа для стратегии продвижения (`STRATEGIA_PROMOVARE.md`) и набора контента (`KIT_CONTINUT.md`)*

У платформы три разных покупателя, и им нельзя говорить одно и то же.
Заказчик покупает результат («магазин работает с моей базой»), разработчик —
удобство («модуль за день, ничего не ломаю»), Oracle — референс («вот так
Autonomous DB живёт в реальном ERP-проекте в Молдове»).

## 1. Разработчики и студии

### Кто это

| Сегмент | Где живут | Боль |
|---|---|---|
| **A. Python/Flask-разработчики**, 2–10 лет опыта | GitHub, Habr, dev.to, Telegram-чаты «Python Moldova / Romania», LinkedIn | ERP-проекты = монолит на 9 000 строк, любое изменение ломает чужое |
| **B. Oracle PL/SQL-разработчики и 1С/ERP-интеграторы** | Oracle Forums, ask.tom, LinkedIn-группы Oracle, конференции Oracle Romania | «веб над Oracle» делают через ORM и отдельную базу — потом вечная синхронизация |
| **C. Студии, внедряющие UNA.md / учётные системы на Oracle** у клиентов | партнёрская сеть una.md, IT Park Moldova | каждый клиент хочет сайт/кабинет/телеграм, писать с нуля дорого |
| **D. Разработчики, работающие с ИИ-агентами** (Claude Code, Cursor, Codex) | X/Twitter, Reddit r/ClaudeAI, Discord Anthropic, YouTube | как не дать агентам затереть работу друг друга в одном репозитории |

### Что им обещаем (value proposition)

- **Модуль = одна папка.** `modules/<ключ>/` с маршрутами, SQL, шаблонами, тестами, документацией. Общий код не трогается — проверяется тестом изоляции.
- **Каркас одной командой**: `python scripts/new_module.py <ключ> "<Название>"` — worktree, ветка, тесты, docs, первый push.
- **Правила, выстраданные на инцидентах**, а не придуманные: `/` вокруг PL/SQL-блоков, `TRANSLATE` с диакритикой, `INSERT…SELECT` в view, затёртый код — всё задокументировано с датой и причиной.
- **Две базы Oracle в одном процессе** (11g thick через воркер + Autonomous thin) — готовый паттерн.
- **Работа с ИИ-агентами как инженерная дисциплина**: `CLAUDE.md`/`AGENTS.md` = стандарт, который агент обязан соблюдать; worktree на задачу; коммит и push каждого шага.

### Что ценят / чего боятся

- Ценят: код, который можно прочитать; честные post-mortem; живое демо, а не слайды.
- Боятся: vendor lock-in, «закрытой коробки», неотвечающего мейнтейнера.

### Какое действие хотим

Склонировать шаблон модуля → написать свой модуль → прислать PR или стать партнёром-внедренцем.

## 2. Oracle (корпорация и экосистема)

### Кто это конкретно

| Адресат | Зачем им мы |
|---|---|
| **Oracle Partner Network (OPN)** — менеджеры по партнёрам в регионе CEE/Румыния | референс-проект на Autonomous Database у SMB-клиента, upsell OCI |
| **Oracle ACE Program / Developer Advocates** | материал для блога/доклада: «модульный Flask-портал над Oracle 11g + 23ai» |
| **Oracle Cloud Marketplace** | листинг «Artgranit — modular web layer for Oracle ERP» (BYOL-образ) |
| **Oracle Romania / региональные user groups (RoOUG)** | доклад на митапе, кейс в рассылке |
| **Команда Oracle APEX / python-oracledb** | реальный пользователь thin+thick в одном приложении, обратная связь по драйверу |

### Что им обещаем

- **Oracle-first архитектура**, записанная как правило №1: нормализованные таблицы с префиксами, DDL отдельно, никакого «state в JSON».
- **Два поколения Oracle в одном продукте**: 11.2 (унаследованная ERP, CL8MSWIN1251) и Autonomous DB 23ai — живая история миграции.
- **Потребление OCI**: Autonomous DB, Compute (92.5.x), wallet-аутентификация — всё по рекомендациям Oracle.
- **Готовность к публикации кейса**: цифры, архитектура, скриншоты — уже в документации.

### Что ценят / чего боятся

- Ценят: измеримое потребление облака, качественную документацию, спикеров.
- Боятся: обещаний без прода, нарушений лицензий (у нас — python-oracledb, без Instant Client-нарушений; 11g используется клиентом по его лицензии).

### Какое действие хотим

Статус OPN-партнёра → совместный кейс (success story) → листинг в Marketplace → доклад на Oracle-мероприятии.

## 3. Обычные заказчики (бизнес)

### Кто это

| Сегмент | Пример | Триггер покупки |
|---|---|---|
| **A. Торговые компании на UNA.md / Oracle** (канцелярия, стройматериалы, техника) | OfficePlus (Бэлць) | «нужен интернет-магазин с живыми остатками и ценами, а не выгрузка раз в сутки» |
| **B. Производство и сервис** (химчистки, прачечные, услуги) | Nufărul | рабочее место оператора + экран клиента + статус заказа онлайн |
| **C. Агро-приёмка, склады** | AGRO | весовая, качество, продажи — в поле, с планшета |
| **D. Ритейл-сети** | планограммы | автозаказ по прогнозу, выкладка, фреш |
| **E. Компании с кредитованием покупателей** | рассрочка через EasyCredit/Iute/Microinvest/MAIB | «цена в рассрочку» прямо на витрине |
| **F. Все плательщики НДС в Молдове** | e-Factura | входящие накладные из SFS — в учёт за минуты |

География: Молдова (RO/RU), Румыния (RO), диаспора/экспорт (EN).

### Что им обещаем

- **Магазин живёт в вашей ERP**: товар, цена, остаток, заказ — одна база, без двойного ввода.
- **Запуск за дни**: 1 день подключение, 1–3 дня магазин и кабинет, интеграции уже написаны.
- **Закон**: e-Factura, согласие на cookie, персональные данные — встроено.
- **Деньги**: рассрочка на витрине, оплата MAIB/MIA, кредиторы подключены.
- **Контроль**: воронка продаж, метрики, соцсети публикуются сами.

### Что ценят / чего боятся

- Ценят: «показали на моих данных», телефон, по которому отвечают, цену без сюрпризов.
- Боятся: «ещё одна система», потери данных, зависимости от одного программиста.

### Какое действие хотим

Звонок/заявка → демо на их базе (1 день) → пилот одного модуля → договор на внедрение + поддержку.
