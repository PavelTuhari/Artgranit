# Консолидация 19.10.2026: все ветки — в `main`, `main` — на всех серверах

**Для кого:** любой ИИ-агент и разработчик, который открывает этот репозиторий в
любой ветке или worktree. Прочитать до первого коммита. Правила из раздела 5 уже
стоят в `CLAUDE.md` (правило №6) и `AGENTS.md` — этот документ объясняет, почему
они появились, и показывает на фактах, что бывает без них.

---

## 1. Что случилось (проблема)

Владелец 19.10.2026: *«посмотри что ты творишь: в проекте утерян код TBControl …
восстановить заново»* — и после разбора: *«все сливай и так чтобы все вместе и
оказалось где надо».*

Разбор показал не одну потерю, а **систему**:

| Симптом | Факт |
|---|---|
| Код TBControl «утерян» | Восстановлен 02.09.2026 (коммит `e9935c67`, 20 тестов, отчёт), но **47 дней лежал на локальной ветке** `claude/sweet-blackwell-5001c9` из `.claude/worktrees/`. На origin попал только при аудите 01.10, в `main` — никогда. `/api/tbc/services` на nufarul всё это время → 500. |
| Правила «не теряем код» не работали | Правила №3–№5 и концепция worktree существовали **только** в `CLAUDE.md` ветки `feat/autopark-module`. В `main` их не было → любая сессия от `main` их не видела. |
| «Всё закоммичено», а на серверах нет | 13 веток с законченной работой (netmon, crm, furnizori, efactura, ultra-sync, biro26-catalog, sda, peco, autopark…) — на origin, но не в `main`, значит, и не на серверах, которые ставятся из `main`. |
| Код живёт только на сервере | На nufarul `app.py` = ветка-слепок `prod/nufarul-live` (orphan-история), с оптимизациями (`_public_cached`, прогрев каталога), которых в git-истории `main` не было. На office/cloud — 8 файлов с ручными патчами (снимки `prod/office-…`, `prod/cloud-…`). |
| Hook «коммитит каждую правку» | Коммитит **локально** в текущую ветку. Push не гарантирует; ветки `claude/*` без push живут на одном Mac. |

Вывод: **работа, которую видно только из одной сессии (ветка без merge, файл только
на сервере, правило только в одной ветке), равна потерянной** — даже если она
«закоммичена».

## 2. Что сделано (решение)

### 2.1 Слияние всех веток в `main`

Порядок — от простого к сложному; каждое слияние = отдельный merge-коммит, после
каждого — весь набор тестов (`pytest tests`), push.

| `feat/ultra-sync`, `feat/biro26-catalog` | 5 / 4 | `--no-ff` | нет |

### 2.3 Все рабочие каталоги — на одном коммите

Все 17 worktree (в т.ч. каталог владельца `/Users/pt/Projects.AI/Artgranit` на
`feat/autopark-module`) переведены fast-forward на `main` и запушены. Открыв любой

Исключение — `Artgranit-prodsnap` (`prod/nufarul-2026-09-28`, слепок, не ff).

### 2.4 Инцидент при выкатке — и правило из него

Первая выкатка TBControl уронила nufarul на ~1 минуту (502): список файлов не
разбился в zsh, архив ушёл пустым, новый `app.py` импортировал отсутствующий модуль.
Откат из `.bak` сразу. Отсюда обязательная последовательность для `app.py`
(раздел 5.5).

## 3. Что изменено в правилах (для всех веток)

`CLAUDE.md` и `AGENTS.md` **в `main`** (и через ff — во всех worktree):

- правила №3 (изолированные файлы + push каждого шага), №4 (чужое не затирать),
  №5 (живые ссылки) и концепция worktree — перенесены из ветки autopark;
- **новое правило №6**: «сделано = в origin + в `main` + на площадке + проверено»,
  аудит в начале и конце сессии, порядок деплоя `app.py`.

Если в вашей ветке `CLAUDE.md` короче, чем в `main`, — **ваша ветка устарела**:
`git merge origin/main` (или ff) прежде чем работать.

## 4. Как проверить, что ничего не потерялось (повторяемо)

```bash
# ветки с работой не в main (должно быть пусто, кроме prod/* и backup/*)
git fetch -q origin && git branch -r --no-merged origin/main
# локальные ветки, которых нет на origin
git for-each-ref --format='%(refname:short)' refs/heads | while read b; do [ -z "$(git branch -r --contains "$b")" ] && echo "НЕ НА ORIGIN: $b"; done
# незакоммиченное в любом worktree
git worktree list --porcelain | awk '/^worktree/{print $2}' | while read d; do n=$(git -C "$d" status --porcelain | grep -v 'venv\|wallet_' | wc -l); [ "$n" != 0 ] && echo "$d: $n"; done
# сервер == main? (на сервере: хэш git каждого файла; сравнить с git ls-tree origin/main)
```

## 5. Правила для агентов в других ветках — коротко (полный текст в CLAUDE.md №6)

1. **Первое действие сессии — аудит** (команды выше). Чужое незалитое/неслитое —
   не трогать, сказать владельцу. Своё — push немедленно.
2. **Шаг → commit → push. Задача → merge в `main` → push `main` → выкатка → `curl` →
   `.md` с датой.** Невыполненный пункт называется в ответе: «не слито, потому что …».
3. **Своё — в своих файлах** (`modules/<ключ>/`, `models/<модуль>_<тема>.py`,
   `static/<модуль>/`, `docs/<Модуль>/`); в общий файл — одна строка вызова,
   точечным `Edit` после `git log -3 -- файл`. `Write` целиком общего файла запрещён.
   Правила и документация тоже общие: новое — **в конец**, чужое не переписывать.
4. **Конфликт при слиянии — не «взять чужую сторону целиком»**: код — та сторона,
   что новее (чаще `main`); `docs.json` — объединение ключей; `.md` — текст `main` +
   блоки ветки в конец; всё спорное — в сообщении коммита. Старую ветку, полностью
   переписанную в новой, сливать `-s ours` с объяснением, чтобы не всплывала снова.
5. **`app.py` на сервер**: список файлов → `tar -T`; пересчитать; распаковать
   **модули**; `[ -f ]` каждого импорта; `py_compile`; `import app`; только потом `cp`
   `app.py`; `restart` → `login` 200 → `journalctl` без Traceback → `curl` снаружи;
   при 502 — `cp app.py.bak-ДАТА app.py && restart` немедленно.
6. **На сервере файл может быть новее `main`** (так было с nufarul `app.py`): перед
   заменой `md5sum` против `git show origin/main:файл`; не совпало — уникальные
   строки **перенести в `main` своим файлом**, и только потом выкатывать `main`.
7. **Ветки `claude/*` из `.claude/worktrees/`** — это тоже работа: push и merge, как
   у любой другой; иначе она существует только на этом Mac.
