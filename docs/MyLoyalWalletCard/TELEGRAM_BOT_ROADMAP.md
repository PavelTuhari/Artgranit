# Роадмап: телеграм-бот продажи билетов и мобильное приложение — один кошелёк

Бот **[@unisim_BileteGarileMD_bot](https://t.me/unisim_BileteGarileMD_bot)** уже
продаёт билеты и указан на garileauto.md как канал продаж. Приложение UNA Market
умеет хранить билет в кошельке, показывать штрихкод и динамический код, проходить
контроль. Задача — сделать так, чтобы это был **один билет одного пассажира**,
а не две несвязанные покупки.

Составлено 12.09.2026 по итогам проверки кошелька (см. `WALLET_PASSES.md`).

---

## Принцип: бот и приложение — два окна в одну платформу

```
      Telegram-бот  ─┐
                     ├─→  Кошелёк платформы (/api/wallet/v1/*)  ─→  Контроль посадки
   Мобильное прил.  ─┘         ↑
                     Система продаж автовокзала (iRuta / garileauto)
```

Билет живёт **в платформе**, а не в чате и не в телефоне. Бот и приложение — два
способа его купить и показать. Отсюда всё остальное: общий держатель, общий
журнал, общий контроль.

---

## Этап 1. Общий пассажир (2–3 дня)

Сейчас бот знает пассажира по `telegram_id`, приложение — по номеру телефона.

| Шаг | Что делаем |
|---|---|
| 1.1 | Бот при первой покупке просит контакт (`request_contact`) — Telegram отдаёт номер, подтверждённый самим Telegram |
| 1.2 | Бот вызывает `POST /api/wallet/v1/auth/verify` в режиме доверенного канала (ключ оператора + номер) — без SMS: номер уже подтверждён |
| 1.3 | В `WalletUser` добавляется поле `telegramId`; один и тот же номер = один держатель |
| 1.4 | Бот показывает: «Ваши билеты также в приложении» со ссылкой на установку |

**Готово, когда:** покупка в боте видна в приложении без единой дополнительной регистрации.

## Этап 2. Билет из бота — в кошелёк (3–4 дня)

| Шаг | Что делаем |
|---|---|
| 2.1 | Бот выпускает билет через `POST /api/wallet/v1/transit/tickets` вместо собственной записи |
| 2.2 | В ответ получает номер билета и подписанный токен; рисует QR прямо в чат (`sendPhoto`) |
| 2.3 | Кнопка «Открыть в приложении» — диплинк `unamarket://pass/<serial>` с запасным веб-адресом |
| 2.4 | Контролёр сканирует один и тот же QR из чата и из приложения — проверка одна |

**Готово, когда:** билет, купленный в боте, гасится на контроле и исчезает из приложения как погашенный.

## Этап 3. Уведомления, которых сегодня нет (2 дня)

Телеграм умеет то, чего не умеет штрихкод на бумаге:

- за час до отправления — напоминание с перроном и местом;
- изменение перрона или задержка — сообщение в чат;
- после поездки — «оцените рейс» и предложение обратного билета;
- возврат билета — подтверждение и статус денег.

Отправка — из платформы через вебхуки, которые уже есть (`WebhookEndpoint`),
получатель — бот. Ничего нового изобретать не нужно.

## Этап 4. Кабинет в боте (3 дня)

Команда `/bilete` — список активных и прошлых билетов из `GET /api/wallet/v1/passes`
с фильтром по держателю. Возврат — `POST /api/wallet/v1/passes/{serial}/revoke`.
Всё то же, что в приложении, но для тех, кто не ставит приложения.

## Этап 5. Оплата внутри Telegram (4–5 дней)

Telegram Payments (провайдер MAIB/MIA, как на сайте) — покупка не выходя из чата:
`sendInvoice` → `pre_checkout_query` → `successful_payment` → выпуск билета.
Сейчас бот уводит на сайт; это теряет часть пассажиров на переходе.

## Этап 6. Мини-приложение Telegram (5–7 дней, опционально)

`Telegram WebApp` с тем же экраном выбора рейса, что в мобильном приложении:
общий код на React Native Web или отдельная лёгкая страница платформы.
Смысл — покупка в три касания внутри чата, с уже известным номером телефона.

---

## Что нужно доработать на стороне платформы

| Доработка | Зачем | Оценка |
|---|---|---|
| Поле `telegramId` в `WalletUser` + связка по номеру | один пассажир в двух каналах | 0,5 дня |
| Режим доверенного канала в `auth/verify` (ключ оператора вместо SMS-кода) | бот не должен слать SMS на подтверждённый Telegram номер | 1 день |
| Диплинк `unamarket://pass/<serial>` и обработка в приложении | переход из чата в билет | 0,5 дня |
| Вебхук `pass.reminder` за N минут до отправления | напоминания | 1 день |
| QR с подписанным токеном картинкой (сервер рисует PNG) | бот не умеет рисовать сам | 0,5 дня |

Итого по платформе — около **3,5 дней**; остальное на стороне бота.

---

## Порядок, если делать быстро

1. Этапы 1 и 2 — это уже даёт единый билет и снимает главную путаницу.
2. Этап 3 — самое заметное для пассажира при малых затратах.
3. Этапы 4–6 — по мере необходимости.

## Чего делать не нужно

- **Дублировать хранение билетов в боте.** Один источник — платформа; иначе
  расхождения при возврате и гашении неизбежны.
- **Свой формат QR для бота.** Формат уже есть и проверяется контролёром офлайн.
- **Отдельный вход по логину и паролю.** Номер телефона и Telegram-контакт закрывают
  все случаи.
