# Стыковка с боевыми серверами автовокзалов: garileauto.md и garaauto.eu

Проверено 12.09.2026. Итог короткий: **платформа готова, программного интерфейса
продаж на боевых серверах нет** — нужен доступ от владельца билетной системы.

## Что стоит на боевых серверах

| | garileauto.md | garaauto.eu |
|---|---|---|
| Кто | Gările Auto Chișinău | Gara Ungheni (BTA28) |
| Владелец билетной части | I.S. Direcția pentru Exploatarea Imobilului (isdei.md) | BTA28 |
| Сайт | WordPress, тема travel-tour | WordPress, «Developed by Unisim-Soft SRL» |

| Кабинет пассажира | `/ticket/user.php?org=gauto` — вход по e-mail с кодом | `/ticket/user.php?org=bta28` |
| Оплата брони | по коду резервации + e-mail, форма `/ticket/pay.php` | так же |
| Telegram | `@unisim_BileteGarileMD_bot` | `@GaraAutoEU_bot` |
| Масштаб | 140+ рейсов в день, 26 направлений | Chișinău, Bălți, Soroca, Iași |

## Результат проверки адаптера

Платформа переключена на боевой адрес: `TRANSIT_SOURCE=iruta`,
`IRUTA_BASE_URL=https://www.garileauto.md`.

```
GET /api/trips   → HTTP 404 (HTML WordPress)   платформа: 503 transit_unavailable
POST /api/orders → HTTP 404                     платформа: 503 transit_unavailable
```

Это **правильное поведение**: при недоступном источнике платформа отдаёт явную
ошибку настройки и не выдумывает рейсы. Демо-расписание (`TRANSIT_SOURCE=mock`)
включается отдельной переменной и никогда не подменяет боевые данные молча.

## Что нужно от билетной системы

Три вызова, после которых переключение делается одной переменной окружения:

| Вызов | Ответ |
|---|---|
| `GET /api/trips?from=&to=&date=` | рейсы: направление, время, перрон, перевозчик, цена, свободные места |
| `POST /api/orders` | бронь: номер заказа, место, цена |
| `POST /api/orders/{id}/refund` | возврат |

Форматы описаны в `WALLET_PASSES.md` (раздел «Источник рейсов») и повторяют то,
что уже возвращает мок-источник — адаптер `src/lib/transit/iruta.ts` готов.

### Вариант без открытия API

Мост по коду резервации: пассажир вводит в приложении **код брони и e-mail**
(как в кабинете `/ticket/user.php`), платформа подтверждает бронь у билетной
системы одним запросом и выпускает пропуск в кошелёк. Требует один вызов вместо
трёх и не открывает наружу продажи.

## Замечание по безопасности (передать владельцу isdei.md)

`https://www.garileauto.md/ticket/` отдаёт предупреждения PHP с путями
файловой системы и упоминанием констант доступа к БД из `env.php`.
Не эксплуатировалось; рекомендуется `display_errors=Off` на публичном контуре.
