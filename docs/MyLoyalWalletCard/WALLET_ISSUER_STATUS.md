# Статус эмитента карт: Apple Wallet и Google Wallet

Что нужно компании, чтобы выпускать **свои** карты лояльности в кошельки — как это делает
Unisim-Soft для своих продуктов. Две независимые регистрации, разные требования и сроки.

Проверено по официальной документации 25.08.2026:
[Apple Developer Program](https://developer.apple.com/programs/enroll/) ·
[Google Wallet Issuer](https://developers.google.com/wallet/retail/loyalty-cards/getting-started/issuer-onboarding)

---

## Коротко

| | Apple Wallet | Google Wallet |
|---|---|---|
| Стоимость | **99 USD в год** | **бесплатно** |
| Юрлицо обязательно | да | желательно (нужно название бизнеса) |
| D-U-N-S номер | **обязателен** | не требуется |
| Срок получения | 2–6 недель (в основном ждём D-U-N-S) | 1–3 дня демо, до 2 недель прод-доступ |
| Что выдают | Pass Type ID + сертификат подписи | Issuer ID + сервис-аккаунт |
| Можно начать сегодня | нет (сначала D-U-N-S) | **да, в демо-режиме** |

**Рекомендация:** начните с Google Wallet — он бесплатный, регистрируется за день и уже
сегодня даёт рабочие карты в демо-режиме. Параллельно запускайте получение D-U-N-S для Apple,
это самая долгая часть.

## 1. Apple Wallet — 99 USD в год

### Требования к компании

| Требование | Пояснение |
|---|---|
| **Юридическое лицо** | Только реальная компания. ИП-псевдонимы, торговые марки, филиалы и «DBA» не принимаются. Название компании станет видимым именем эмитента. |
| **D-U-N-S номер** | Девятизначный код от Dun & Bradstreet. Обязателен для всех организаций. Выдаётся бесплатно, но занимает от 5 рабочих дней до 3–4 недель. Проверить существующий и запросить новый: [страница проверки Apple](https://developer.apple.com/enroll/duns-lookup/). |
| **Право подписи** | Заявку подаёт владелец, руководитель или сотрудник с письменными полномочиями подписывать договоры от имени компании. |
| **Рабочая почта на своём домене** | `name@вашдомен.md`. Gmail и подобные не принимаются. |
| **Действующий сайт на своём домене** | Публичный, с содержанием. Ссылка на соцсеть или страница-заглушка регистратора не подойдут. |
| **Физический адрес** | Не абонентский ящик. |
| **Apple ID с двухфакторной аутентификацией** | Личный Apple ID заявителя, обязательно с настоящими именем и фамилией. |

### Порядок действий

1. **Получить D-U-N-S** (самый долгий шаг — начните с него).
2. Зарегистрироваться: [developer.apple.com/programs/enroll](https://developer.apple.com/programs/enroll/) → «Начать регистрацию» → выбрать **Company/Organization**.
3. Дождаться проверки Apple (обычно 2–7 дней, могут позвонить для подтверждения полномочий).
4. Оплатить 99 USD — членство активируется.
5. В разделе **Certificates, Identifiers & Profiles**:
   - создать **Pass Type ID**, например `pass.md.rogob.loyalty`;
   - выпустить для него **сертификат Pass Type ID** (загрузить CSR, скачать `.cer`);
   - скачать промежуточный сертификат **Apple WWDR**.
6. Передать три файла в платформу (см. раздел 3).

### Что даёт

Подписанные `.pkpass`, обновление баланса «по воздуху» через APNs, показ карты на экране
блокировки рядом с магазином (геолокация), NFC-считывание (опционально, через VAS).

## 2. Google Wallet — бесплатно

### Требования

Юридические требования мягче: нужен Google-аккаунт и публичное название бизнеса.
Плата за выпуск карт не взимается.

### Порядок действий

1. Открыть [Google Pay & Wallet Console](https://goo.gle/wallet-console), войти
   рабочим Google-аккаунтом (он получит роль **Admin**).
2. Указать публичное название бизнеса, принять условия Google Wallet API.
3. Нажать «Create a pass» → «Build your first pass» — создаётся **Issuer ID**.
4. Создать проект в Google Cloud, включить **Google Wallet API**, завести
   **сервис-аккаунт**, скачать JSON-ключ.
5. В консоли выдать этому сервис-аккаунту доступ к Issuer-аккаунту.
6. Создать **LoyaltyClass** — шаблон карты (логотип, цвета, название программы).
7. Запросить **production access** в разделе Google Wallet API Dashboard.

### Демо-режим и продакшен

Новый аккаунт работает в **демо-режиме**: карты сохраняются только у пользователей с ролью
Admin/Developer или добавленных как тестовые. Функционально всё то же самое — можно
показывать заказчику. Для выдачи карт всем покупателям запрашивается production access.

## 3. Что уже готово в платформе

Код выпуска карт написан и ждёт только учётных данных — доработка не потребуется.

| Файл | Назначение |
|---|---|
| `src/lib/wallet.ts` | сборка карты для обоих кошельков, проверка готовности настроек |
| `src/app/api/wallet/apple/[code]/route.ts` | выдача подписанного `.pkpass` |
| `src/app/card/[code]/page.tsx` | кнопки «Apple Wallet» / «Google Wallet» на карте клиента |

Кнопки на веб-карте активируются автоматически, как только заданы переменные окружения.
Пока их нет — кнопки неактивны с пояснением, а карта работает как веб-карта и PWA.

### Переменные окружения

```bash
# Google Wallet
GOOGLE_WALLET_ISSUER_ID=3388000000012345678
GOOGLE_WALLET_SA_EMAIL=wallet@проект.iam.gserviceaccount.com
GOOGLE_WALLET_SA_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
GOOGLE_WALLET_CLASS_SUFFIX=rogob_loyalty

# Apple Wallet
APPLE_PASS_TYPE_ID=pass.md.rogob.loyalty
APPLE_TEAM_ID=XXXXXXXXXX
APPLE_PASS_CERT_PEM="-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n"
APPLE_PASS_KEY_PEM="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
APPLE_WWDR_CERT_PEM="-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n"
```

Задаются в systemd-юните `/etc/systemd/system/myloyalwallet.service` (строки `Environment=`),
после правки: `sudo systemctl daemon-reload && sudo systemctl restart myloyalwallet`.

**Ключи и сертификаты в репозиторий не коммитятся.** На сервере файл юнита читается только
root; при росте требований к безопасности вынесите значения в отдельный файл с правами `600`
и подключите через `EnvironmentFile=`.

### Конвертация сертификатов Apple в PEM

Apple выдаёт `.cer` (DER) и ключ в связке ключей. Приведение к формату для переменных:

```bash
# сертификат Pass Type ID
openssl x509 -inform DER -in pass.cer -out pass-cert.pem

# приватный ключ: экспортировать из Связки ключей в pass.p12, затем
openssl pkcs12 -in pass.p12 -nocerts -nodes -legacy -out pass-key.pem

# промежуточный сертификат Apple WWDR
openssl x509 -inform DER -in AppleWWDRCAG4.cer -out wwdr.pem
```

## 4. Порядок для Rogob

1. **Сегодня:** зарегистрировать Google Wallet Issuer (бесплатно, ~1 час) → карты в Google Wallet
   работают в демо-режиме, можно показывать заказчику.
2. **Сегодня же:** запросить D-U-N-S на юрлицо — это самое долгое звено.
3. **После получения D-U-N-S:** оформить Apple Developer Program (99 USD), выпустить
   Pass Type ID и сертификат.
4. **Передать учётные данные** — карты в обоих кошельках включатся без изменений кода.
5. Запросить production access в Google, когда программа выйдет на реальных покупателей.

Пока статуса нет, покупатели не остаются без карты: работают веб-карта со штрихкодом Code128
и PWA на домашнем экране (см. `OWN_APP_STORE.md`).
