# Релиз на прод: точечный патч, архив и откат

Инструмент: `scripts/prod_release.py`. Контур — nufarul
(`92.5.3.187`, `/home/ubuntu/artgranit`, служба `artgranit`).
Контур officeplus.md обновляется отдельно и только с разрешения
владельца (см. `CLAUDE.md`).

## Зачем он, если есть `deploy_to_remote.sh`

`deploy_to_remote.sh` распаковывает на сервер **весь проект**. Над
репозиторием одновременно работают несколько веток и несколько сессий, и
на проде вполне может лежать чужой свежий деплой, которого в твоей ветке
нет. Полная распаковка затрёт его молча: конфликта не будет, коммита не
будет, узнают через неделю.

`prod_release.py` везёт **только перечисленные файлы** и перед отправкой
сверяет каждый с тем, что реально лежит на сервере.

## Как он отличает своё от чужого

Для каждого файла берутся три хэша: локальный, серверный и **все версии
этого файла в истории ветки**.

| Ситуация | Вывод | Что делает |
|---|---|---|
| хэши совпадают | `уже совпадает` | не отправляет |
| на сервере нет файла | `новый файл` | отправляет |
| серверный хэш есть в истории ветки | `на сервере более старая наша версия` | отправляет |
| серверного хэша в истории **нет** | `ЧУЖАЯ версия` | **останавливает релиз** |

Сравнения с одним только HEAD недостаточно: сервер почти всегда отстаёт
на несколько коммитов, и без истории каждый такой файл выглядел бы чужим.
Инструмент кричал бы на ровном месте, а на настоящую чужую правку никто
бы уже не посмотрел.

## Порядок работы

```bash
# 1. Собрать список файлов релиза (по умолчанию — последний коммит)
git diff --name-only HEAD~3 HEAD | grep -v '^docs/Planograms' > /tmp/release.txt

# 2. Посмотреть, что изменится. Ничего не отправляется
venv/bin/python scripts/prod_release.py --check --paths-from /tmp/release.txt

# 3. Выкатить: архив -> отправка -> systemctl restart -> проверка
venv/bin/python scripts/prod_release.py --deploy --paths-from /tmp/release.txt

# 4. Список точек возврата
venv/bin/python scripts/prod_release.py --list

# 5. Откат
venv/bin/python scripts/prod_release.py --rollback 20260919_0013
```

## Что происходит при `--deploy`

1. **Анализ.** Если найдена чужая версия хоть одного файла — релиз
   останавливается. Перезаписать можно только осознанно: `--force-foreign`,
   и это останется в выводе.
2. **Архив.** В `/home/ubuntu/artgranit_releases/<штамп>.tar.gz`
   складываются **те же самые пути**, снятые с сервера ДО замены, плюс
   `<штамп>.files` со списком. Архивируется только затрагиваемое, а не
   весь проект: полный архив — это десятки мегабайт и медленный откат,
   а вернуть нужно ровно то, что меняли. Хранятся последние 10 точек.
3. **Отправка.** Точечный tar.gz с `COPYFILE_DISABLE=1` (без него macOS
   кладёт в архив двойники `._имя`, и они приезжают на сервер).
4. **Перезапуск.** `sudo systemctl restart artgranit` — никаких
   `pkill` + `nohup`, это увело бы процесс из-под systemd.
5. **Проверка.** Три условия сразу: `127.0.0.1:8000/login` = 200,
   `https://nufarul.eminescu.md/login` = 200, в журнале за минуту нет
   `ModuleNotFound` и `Traceback`. Не сошлось — **автоматический откат**
   на только что снятую точку.

## Что происходит при `--rollback`

Перед распаковкой архива инструмент снимает **новую** точку возврата с
суффиксом `_before_rollback`: откат тоже бывает ошибкой, и вернуться
вперёд надо уметь. Дальше — распаковка, рестарт и те же три проверки.

Откат возвращает **только файлы из архива**. Файлы, которых на сервере
раньше не было (новые модули релиза), останутся на диске, но станут
неактивными: старая версия точки входа их не импортирует. Это нормальный
и безопасный откат — код не исполняется, следующий релиз их перезапишет.

   (новый API отдаёт 404, модуль работает в прежней версии, домен жив)

Непроверенный откат — это не откат, поэтому он прогоняется на самом
проде, а не описывается на словах.

## Ограничения, о которых надо знать

1. **Oracle-объекты инструмент не разворачивает.** DDL ставится своим
   установщиком модуля (`modules/<ключ>/scripts/<ключ>_deploy.py`) и
   откатом файлов не отменяется: снятая колонка или новая таблица
   останутся. Все DDL модуля написаны так, чтобы старый код их просто не
   замечал (только добавления, никаких DROP COLUMN), поэтому откат кода
   безопасен при новой схеме. Обратное неверно: не откатывайте схему под
   работающим новым кодом.
2. **Удаление файлов не переносится.** Инструмент только добавляет и
   заменяет. Файл, удалённый локально, на сервере останется — это
   осознанный выбор: молча удалять на проде опаснее, чем оставить лишнее.
3. **venv, `.env` и wallet не трогаются никогда** — они не входят ни в
   патч, ни в архив.
