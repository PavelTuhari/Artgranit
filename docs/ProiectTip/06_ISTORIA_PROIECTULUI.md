## 6.5 Этап IV — ядро и изолированные модули (08.2026)

Причина этапа — **потери работы**, а не стиль кода:

| Дата | Что случилось | Чем ответили |
|---|---|---|
| 31.07 | сайт дважды падал с 500 на ~2 минуты: скрипт деплоя удалял каталог вместе с `venv` | venv переносится в сторону и возвращается; «venv неприкосновенен»; защитные файлы на сервере |
| 31.07–05.08 | заморозка работ по архивам | архив деплоя 37 МБ вместо 480 МБ (исключения), заморозка снята 05.08 |
| 19.08 | nufarul 502 на полторы минуты: отправлен `app.py`, импортирующий модули, которых нет на сервере | правило «`app.py` — только вместе с модулями, проверка после каждого рестарта» |
| 22.08 | параллельная сессия затёрла правила VPN и деплоя в `CLAUDE.md` | восстановлено из коммита; правило №2 «не писать важное в общие файлы» |

Решение — **ядро подключения модулей** (25.08, `core/module_loader.py`):

1. модуль — это папка `modules/<ключ>/` (маршруты, валидация, SQL, правила без БД,
   шаблоны, DDL со своим установщиком, `module.json` для меню);
2. ядро само находит модуль и подключает под его адресом; на время импорта модуля
   правка общих маршрутов **запрещена**, а не просто проверяется;
3. меню собирается из карты маршрутов — модуль не может оказаться «невидимым»;
4. в каждом модуле два теста изоляции: общий `app.py` его не упоминает, общий
   установщик DDL не тронут.

Первым на ядро переехал **SEOForge** (25.08: таблицы `YSEO_*`, план/факт, ROI по
каналам, перенос в боевую ERP). Вторым — **SDA** (25.08, депозитная система упаковки:
участники, реестр EAN, тарифы с периодами, досье, отчёты). На SDA же поймана
DDL-ловушка: файл пережил четыре ревью и не ставился — `/` стоял только после
PL/SQL-блока. Правило: `/` до и после каждого блока, установщик прогнать вживую.

В тот же период — **PECO** (19.08, АЗС: смены, сверка, отпуск топлива как конечный
автомат, цистерны) и **Планограммы** (15–20.08: выкладка, четыре модели прогноза,
источник данных PECO, 3D-план), **Бэк-офис UNA в вебе** (25.08: журналы, документы,
проводки), **Воронка продаж** и **Соцсети** (26–27.08), **Partner B2B API** (28.08:
контракт 1-в-1 с Ultra B2B API V1).

## 6.7 Этап VI — консолидация и типовой проект (10.2026)

- **19.10** — разбор: восстановленный 02.09 код TBControl **47 дней** пролежал на
  несли́той локальной ветке, а `/api/tbc/services` всё это время отвечал 500. Принято
  **правило №6**: сделано = commit + push + слияние в `main` + выкатка + живая проверка
  + запись в `docs/`. В тот же день **13 веток слиты в `main`**, `main` выкачен на три
  сервера (`docs/Git/GIT_CONSOLIDARE_2026-10-19.md`). Инцидент выкатки: архив ушёл
  пустым (zsh не разбил список), nufarul ~1 минуту отдавал 502 — откат из `.bak`,
  новый порядок деплоя `app.py`.
- **22.10** — найдено, что при консолидации конфликты решались «файл целиком»:
  пропали боковая панель категорий и поиск Oracle Text. Куски восстановлены
  трёхсторонним слиянием по датам (`docs/Git/RESTAURARE_2026-10-22.md`), правило:
  конфликт — только по блокам, новее побеждает. WordPress-админка тоже поставлена на
  паузу тем же `SITE_PAUSE`.
- **25.10** — пакет «типовой проект» (этот комплект), цифры платформы обновлены во всех
  материалах; решение владельца — **все материалы только на nufarul.eminescu.md**,
  officeplus.md на паузе целиком, включая страницы материалов.

## 6.10 Что это значит для тиражирования

1. **Фундамент дорогой, повтор — дешёвый.** Biro26 строился три месяца (06–08.2026;
   за эти месяцы ~2 000 коммитов вместе с параллельными модулями), потому что одновременно изучалась ERP, писались интеграции и
   правила. Для нового клиента на той же ERP эти работы не повторяются — отсюда оценка
   3–5 дней в [Тиражировании](03_REPLICARE.md).
2. **Дольше всего — данные клиента**, а не код: наборы импорта 10–14 заняли две недели
   августа, и каждый находил новый дефект. Закладывать время на первые 2–3 прайса
   поставщиков.
3. **Правила №1–№6 — часть продукта.** Каждое появилось после реальной потери;
   при тиражировании их нельзя «упростить».
4. **Пауза, cookie, ассистент, e-Factura** — готовые модули последних месяцев,
   включаются настройкой, а не разработкой.
