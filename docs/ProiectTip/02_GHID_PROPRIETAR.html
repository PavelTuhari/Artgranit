2. Документация собственника бизнеса

Для владельца и директора. Без технических подробностей — что даёт система, как её контролировать, чем управлять самому и какие решения остаются за вами.

2.1 Что у вас есть

Одна база — ваша учётная система (UNA.md на Oracle). Вокруг неё — веб-модули:

                    ┌──────────── Покупатели ────────────┐
                    │  витрина · кабинет · ассистент      │
                    └──────────────┬──────────────────────┘
   банки, кредиторы ◄──────────────┤
   e-Factura (SFS)  ◄──────────────┤            ┌───────── Сотрудники ─────────┐
   поставщики, Ultra ◄─────────────┤            │ бэк-офис · CRM · e-Factura    │
   соцсети, Telegram ◄─────────────┤            │ отчёты · воронка · соцсети    │
                                   ▼            └──────────────┬────────────────┘
                     ┌──────────────────────────────────────────▼──┐
                     │      ВАША БАЗА: товары, цены, остатки,        │
                     │      клиенты, документы, заказы               │
                     └───────────────────────────────────────────────┘

Главное свойство: данные не копируются. Цена, которую видит покупатель, — та же строка в базе, что у бухгалтера. Заказ с сайта — сразу документ в учёте.

2.3 Ежедневный контроль (10 минут)

Что смотреть Где Норма Если не так
Новые заказы и зависшие Воронка продаж зависших нет менеджеру — связаться с клиентом
Заявки на рассрочку Рассрочка → заявки обработаны в течение дня проверить ответ кредитора
Уведомления в Telegram бот магазина заказы и КП приходят проверить настройки уведомлений
Сайт открывается https://officeplus.md/ страница магазина см. 2.7
Новые входящие e-Factura e-Factura → входящие загружены в учёт бухгалтеру — импорт (инструкция 4b)

Раз в неделю: воронка за неделю (конверсия, средний чек), отчёт по рекламе (SEOForge), публикации в соцсетях.

2.4 Переключатели, которыми вы управляете сами

Все настройки хранятся в базе (YBIRO_SETTINGS), а не в программе: их изменение не требует программиста и не теряется при обновлениях.

Что Где меняется Что происходит
Пауза сайта («ведутся технические работы») https://officeplus.md/UNA.md/orasldev/sitepause/ витрина и вход в WordPress показывают страницу работ (503); бэк-офис и API партнёров работают; действует ≤ 20 с
Текст страницы паузы RO / RU там же свой текст вместо стандартного
Часы работы в шапке сайта SHOP_HOURS «Astăzi lucrăm de la … până la …» по дню недели
Чат JivoChat SHOP_JIVO_ID (экран уведомлений) пусто — чата нет
Google Analytics SHOP_GA_ID запускается только с согласия посетителя
Колонка цены для физлиц / юрлиц SHOP_PRICE_FIZ, SHOP_PRICE_JUR какую цену видит покупатель
Порог рассрочки CREDIT_MIN_ORDER ниже суммы рассрочка недоступна, условие красным
Наценка для новых товаров из e-Factura EFA_PRICE_BELOW_SALE_PCT (по умолчанию 10) цена продажи = цена закупки / (1 − %)
Telegram-уведомления NOTIFY_TG_* заказы и коммерческие предложения уходят менеджеру

2.5 Деньги

Поток Как устроено Ваше действие
Оплата картой MAIB / MIA — договор с банком, ключи в настройках сервера договор с банком
Рассрочка пакеты кредиторов в базе; цена в рассрочку = цена × (1 + наценка пакета + надбавка организации) — одинаково на витрине, в корзине и в счёте договоры с кредиторами, пакеты
Коммерческие предложения PDF из ассистента + уведомление менеджеру менеджер перезванивает
Партнёры B2B заказы через API на клиента-партнёра заключить договор, выдать доступ

2.6 Закон

Требование Как выполнено
Персональные данные / cookie баннер согласия при первом визите: «Refuz» так же заметен, как «Accept»; аналитика, чат, карта и рекламные метки — только после согласия; выбор хранится 180 дней; ссылка «Setări cookie» в подвале
Политика конфиденциальности страница сайта; раздел про cookie подготовлен (docs/Biro26/COOKIE_CONSIMTAMINT_2026-10-09.md) — публикуется после вашего утверждения
e-Factura входящие накладные — импорт в учёт; исходящие — через модуль e-Factura
Поиск Google во время работ пауза отдаёт код 503 и «Retry-After» — страницы не выпадают из индекса

2.7 Если что-то не работает

Признак Первое действие
Сайт показывает «технические работы» проверить переключатель паузы — возможно, она включена намеренно
Сайт не открывается вовсе сообщить внедренцу; бэк-офис и база при этом обычно живы
Не приходят уведомления экран уведомлений → проверка Telegram
Неверная цена на сайте бэк-офис → Listă de prețuri; правило цены — 2.4
Товара нет на сайте у товара нет цены или группы — бэк-офис → Nomenclator

2.8 Надёжность и сохранность

  • Каждое изменение программы — в git с описанием; перед заменой файлов на сервере делается резервная копия.
  • Три контура: боевой (officeplus.md), резервный (облако, подхватывает сайт при сбое офиса), тестовый (nufarul.eminescu.md, та же база).
  • Правила для разработчиков и ИИ-агентов записаны (CLAUDE.md): работа считается сделанной, только когда она в общем репозитории, на сервере и проверена вживую.
