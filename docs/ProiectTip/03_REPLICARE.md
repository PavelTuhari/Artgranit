# 3. Тиражирование: как развернуть типовой проект для другой компании

*Для собственника нового клиента и внедренца. Образец — OfficePlus; ниже — что
повторяется как есть, что настраивается и что делается заново.*

## 3.1 Подходит ли проект клиенту

| Условие | Обязательно? | Комментарий |
|---|---|---|
| Учёт в UNA.md (или другая ERP) на **Oracle** | да | платформа читает и пишет прямо в базу; поддерживаются Oracle 11g и Autonomous Database 23ai |
| Справочник товаров с ценами и остатками | да | источник витрины |
| Сервер Linux (или облако OCI) | да | ~2 vCPU, 4–8 ГБ ОЗУ на контур |
| Домен и почта | да | SSL — Let's Encrypt, бесплатно |
| Договор с банком (MAIB / MIA) | для оплаты картой | |
| Договоры с кредиторами | для рассрочки | EasyCredit, Iute, Microinvest, MAIB — уже подключены в коде |
| Доступ к e-Factura (SFS) | для импорта накладных | сертификат / API-доступ клиента |

| Витрина, корзина, кабинет, ассистент, cookie, пауза | ✓ | логотип, цвета, тексты, контакты, домен | |
| Рассрочка | ✓ | пакеты и надбавки кредиторов в базе | |

## 3.3 Шаги внедрения

| № | Шаг | Кто | Срок | Проверка |
|---|---|---|---|---|
| 1 | Аудит базы клиента: схема, товары, цены, остатки, группы | внедренец | 0,5 дня | список колонок цен, число позиций с ценой |
| 2 | Сервер: Python 3.12, systemd-служба, nginx, SSL; Oracle wallet **вне** каталога кода | внедренец | 0,5 дня | `https://<домен>/login` → 200 |
| 3 | Код из `main` (git), `.env` клиента (подключение к Oracle, ключи банков) | внедренец | 1 час | служба запускается, 0 ошибок в журнале |
| 4 | DDL модулей — **своим установщиком каждого модуля** (`modules/<ключ>/scripts/<ключ>_deploy.py`), один раз вживую | внедренец | 0,5 дня | объекты видны в `USER_OBJECTS` |
| 5 | Настройки в `YBIRO_SETTINGS`: цены, часы, JivoChat, GA, Telegram, порог рассрочки | собственник + внедренец | 1 час | витрина показывает правильные цены |
| 6 | Брендинг: логотип, цвета, тексты страниц (WordPress или страницы витрины), контакты, страница паузы | маркетолог | 1 день | сравнение с макетом |
| 7 | Включить паузу, проверить всё на тестовом контуре, снять паузу | собственник | 1 день | чек-лист 3.5 |
| 8 | Обучение сотрудников по инструкции 4b | внедренец | 1 день | сотрудник сам проводит заказ и импорт e-Factura |
| 9 | Реклама и соцсети по маркетинговому пакету | маркетолог | по плану | первые заявки |

Итого базовый запуск: **3–5 рабочих дней** (без договоров с банками и кредиторами,
которые идут параллельно со стороны клиента).

## 3.4 Правила, которые нельзя нарушать при тиражировании

1. **Данные только в Oracle**, нормализованные таблицы со своим префиксом модуля; никаких JSON-файлов и SQLite как источника правды.
2. **Новый функционал — новым модулем** в `modules/<ключ>/` (каркас: `python scripts/new_module.py <ключ> "<Название>"`); общий код не править.
3. **Секреты не в git**: `.env`, wallet, ключи банков — только на сервере.
4. **Каждое изменение — commit, push, merge в `main`, выкатка, проверка `curl`, запись в `docs/`** (правило №6 в `CLAUDE.md`).
5. **При слиянии веток конфликты — только по блокам, по дате**, никогда «файл одной стороны целиком» (`docs/Git/RESTAURARE_2026-10-22.md`).
6. **Перед заменой файла на сервере** — сверка md5 с git и резервная копия рядом.

## 3.5 Чек-лист приёмки

| Проверка | Как | Ожидается |
|---|---|---|
| Вход в бэк-офис | `https://<домен>/login` | 200, вход работает |
| Витрина | главная, каталог, карточка, поиск «бумага» | товары с ценами и фото |
| Наличие | товар со складом поставщика | «În stoc» / «La comandă» |
| Корзина и рассрочка | товар ниже и выше порога | ниже — условие красным, кнопки рассрочки неактивны |
| Оплата | тестовый платёж банка | ответ банка, документ в учёте |
| Ассистент | поиск, корзина, проверка заказа | розничная цена, «Order is valid (not created)» |
| Cookie | первый визит в новом окне | баннер; до выбора — ни одного запроса к Google/Jivo |
| Пауза | включить → `https://<домен>/` | 503 «технические работы», бэк-офис доступен |
| e-Factura | загрузить тестовый XML | накладные в учёте, штрихкоды, цены |
| Мобильная версия | телефон | нижняя панель навигации, кнопки не перекрываются |
| Резерв | остановить основной контур | резервный подхватывает витрину |

## 3.6 Что подготовить клиенту до старта (письмо-запрос)

> Для запуска нам понадобится: (1) доступ к базе учёта (пользователь Oracle только для
> нужных схем); (2) домен и доступ к DNS; (3) логотип, цвета, тексты «О нас», «Доставка»,
> «Возврат», «Политика конфиденциальности»; (4) реквизиты и контакты для подвала сайта;
> (5) договор с банком для оплаты картой и с кредиторами для рассрочки; (6) доступ к
> e-Factura (если нужен импорт накладных); (7) список сотрудников и их роли.
