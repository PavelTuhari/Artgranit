# ТЗ Bemol — конспект

> Источник: docx-файл клиента, «Автоматизация расчета заработной платы
> водителей бензовозов, контроля маршрутов и расхода топлива».
> Оригинал лежит в `docs/Planograms/Bemol Автоматизация расчета
> расходов АВТОПАРКА.docx` (общий каталог планограмм — это не ошибка
> размещения, файл клиент прислал туда). Этот файл — краткий конспект по
> разделам для быстрой сверки с реализацией, не подменяет исходник.

## 1. Цель проекта

Автоматизировать расчёт зарплаты водителей бензовозов, контроль
маршрутов доставки нефтепродуктов, расхода ДТ и выявление необоснованных
отклонений по пробегу, маршрутам и объёмам перевозок.

## 2. Основные принципы

Зарплата = нормативный пробег × 2.75 лея/км + 600 леев за каждый
внутренний рейс по Молдове. Расчёт — автоматический, по маршруту,
нормативным расстояниям и утверждённому количеству рейсов. Цель —
исключить начисление за необоснованный пробег.

## 3. Справочники

АЗС (код, наименование, адрес, вместимость резервуаров); пункты загрузки
(Кишинёв, МСПД, Констанца, другие — с возможностью добавления);
автомобили (госномер, марка, вместимость, секции, норма расхода);
водители (ФИО, табельный номер, закреплённый автомобиль); матрица
расстояний (загрузка→АЗС, АЗС→АЗС, АЗС→конец маршрута,
загрузка→конец); типы рейсов (внутренний/импортный).

## 4. Источники данных

Учёт нефтепродуктов на АЗС (начальный/конечный остаток, реализация,
поступления, вместимость); закупки и логистика (дата, объём, продукт,
пункт загрузки, АЗС, авто, водитель); GPS/мониторинг (факт. пробег,
маршрут, время движения).

## 5. Формирование рейсов

Рейс формируется при регистрации накладных, может включать одну или
несколько АЗС; маршрут хранится в порядке фактического обслуживания
(пример: Загрузка → Оргеев → Бельцы → Сороки → конец маршрута).

## 6. Определение количества рейсов

Вариант 1 — автоматически (дата, авто, водитель, пункт загрузки,
последовательность АЗС, время выполнения, вместимость, факт завершения).
Вариант 2 — вручную логистом (дата, авто, водитель, тип, пункт загрузки,
последовательность АЗС, конечный пункт, признак завершения). После
утверждения логистом рейс — основание для зарплаты.

## 7. Автоопределение потребности и планирование поставок

Минимальный страховой запас ≥ 6 дней среднесуточной реализации:
`мин.запас = среднесуточная реализация × 6`. Запас в днях = остаток /
среднесуточная реализация. Объём поставки учитывает остаток, мин.
запас, прогноз реализации, объём в пути, вместимость резервуара.
Система определяет: перечень АЗС на поставку, объём по каждой, число
рейсов, объединение АЗС в один рейс, последовательность посещения, тип
и вместимость бензовоза — с минимизацией пробега и числа рейсов.

## 8. Расчёт нормативного пробега

Пробег считается по каждому участку отдельно (загрузка→АЗС1, АЗС1→АЗС2,
…, последняя АЗС→конец) и суммируется. Последовательность доставки
меняет пункт отправления для каждого следующего участка.

## 9. Контроль эффективности маршрутов

Система ищет оптимальный маршрут с минимальным пробегом; при наличии
GPS сравнивает норматив и факт: `отклонение = факт − норматив`,
отклонения сверх лимита — в отчёты контроля.

## 10. Расчёт зарплаты

`Оплата за км = норм.пробег × 2.75`. `Оплата за рейс = 600 леев за
каждый ЗАВЕРШЁННЫЙ ВНУТРЕННИЙ рейс` (число АЗС в рейсе не влияет).
Импортные рейсы (в т.ч. Кишинёв–Констанца–Кишинёв) доплату не получают.
`Зарплата = норм.пробег × 2.75 + внутр.рейсы × 600`.

## 11. Контроль начислений

Система определяет: число внутренних/импортных рейсов, норм. пробег по
рейсу, сумму за км, сумму за рейсы, итоговую зарплату за период.

## 12. Контроль расхода ДТ

`Норм. расход = норм.пробег × норма расхода / 100`. Сравниваются
норматив, факт, отклонение.

## 13. Контроль нарушений

Необоснованный доп. пробег, отклонения маршрута, перерасход топлива,
неэффективные маршруты, несоответствие поставок расчётной потребности
АЗС, неэффективное использование вместимости бензовозов, ошибочная
классификация внутренних/импортных рейсов.

## 14. Отчётность

По водителю: внутр./импортные рейсы, норм./факт. пробег, зарплата,
отклонения. По автомобилю: рейсы, объём, норм./факт. расход,
отклонения. По АЗС: расчётная потребность, факт. поставки, число
поставок, отклонения. Сводный отчёт: сумма зарплаты, общий
норм./факт. пробег, общий перерасход топлива, рейтинг водителей по
эффективности. Отчёт руководству: пробег по автомобилю, стоимость
перевозки 1 л топлива, средняя загрузка бензовозов, перерасход
топлива, число отклонений, экономический эффект от оптимизации
маршрутов.

## Известные допущения реализации (см. отчёты задач 2-3)

- Классификация рейса (п.10) берётся по признаку `IS_FOREIGN` пункта
  загрузки; у конечных пунктов такого признака в схеме нет (первая
  очередь).
- «Стоимость перевозки 1 л» в отчёте руководства считается только по
  зарплатной части — у модуля нет источника закупочной цены топлива.
- Планирование поставок (п.7) и автоформирование рейсов (п.6, вариант
  1) — жадные эвристики (ближайший сосед, набивка по срочности), не
  оптимизатор VRP/bin-packing.
- «Экономический эффект от оптимизации маршрутов» (п.14, сводный
  отчёт) не реализован отдельным полем — первая очередь ограничивается
  наблюдаемыми отклонениями (км, топливо) в `management_report`.
