# Autopark — пакет отчётности (ТЗ §14): XLSX и PDF

Шесть отчётов поверх живых данных Oracle `FLT_*`, с выгрузкой в Excel и
PDF одним CLI-скриптом. Код: `modules/autopark/reports.py` (сборка
данных) + `modules/autopark/scripts/autopark_reports.py` (XLSX/PDF/CLI).
Готовые примеры за июль 2026 и YTD — в `docs/Autopark/examples/`.

## Состав пакета

| Ключ | Отчёт | Что внутри (ТЗ §14) |
|---|---|---|
| `driver` | По водителям | внутр./импортные рейсы, норм./факт. пробег, отклонение, зарплата, число рейсов сверх лимита |
| `truck` | По автомобилям | рейсы, перевезённый объём, норм./факт. расход ДТ, перерасход |
| `station` | По АЗС | остаток, мин. запас, запас в днях, расчётная потребность, фактические поставки (число и литры), отклонение |
| `summary` | Сводный | итоги зарплаты/пробега, суммарный перерасход ДТ, **рейтинг водителей по эффективности маршрутов** |
| `management` | Для руководства | пробег, стоимость перевозки 1 л, средняя загрузка бензовозов, число отклонений, экономический эффект |
| `prices` | Ценовой (дополнительный) | динамика ANRE за период (min/max/среднее, число изменений), влияние цен на стоимость нормативного расхода ДТ парка |

## Контракт reports.py

Каждая функция `report_*(date_from, date_to)` возвращает единый словарь:

```python
{"title": str, "period": "YYYY-MM-DD — YYYY-MM-DD",
 "columns": [str, ...],
 "rows": [[...], ...],      # каждая строка ровно len(columns)
 "totals": [...] | [],      # строка итогов той же ширины или пусто
 "notes": [str, ...]}       # допущения и пояснения
```

На этом контракте построены обе выгрузки и часть команд бота; ширина
строк и сортировка рейтинга закреплены тестами
(`tests/test_autopark.py::test_reports_contract_every_report` и далее).
Ошибка нижнего слоя (Oracle недоступен, view не отвечает) поднимает
`AutoparkReportError` — выгрузка падает явно, а не отдаёт пустой отчёт.

Данные тянутся ТОЛЬКО через существующие методы
`AutoparkStore`/`AutoparkController` (`driver_summary`, `truck_summary`,
`station_supply_report`, `trip_control_report`, `trip_pay_report`,
`list_trips`, `list_fuel_prices`, `management_report`) — новых SQL в
store для отчётности не понадобилось.

## Зафиксированные допущения

1. **Экономический эффект** (management) — оценка
   `(факт. пробег − норм. пробег) × ставка за км` (2.75 из
   `FLT_SETTINGS.RATE_PER_KM`): положительное значение — переплаченные
   леи за необоснованный пробег, отрицательное — экономия против
   норматива. Стоимость топлива в оценку не входит.
2. **Стоимость перевозки 1 л** — только зарплатная часть (см. допущение
   `management_report` в TZ_BEMOL.md): закупочной цены топлива у модуля
   нет.
3. **Рейтинг водителей** (summary) — `|факт − норма| / норма × 100%`,
   по возрастанию; водители без фактического пробега (GPS не покрыл ни
   одного рейса) — в конце списка.
4. **Расчётная потребность** (station) — дефицит до минимального
   страхового запаса на текущую дату `max(0, мин.запас − остаток)`;
   полная формула планирования (прогноз, объём в пути, вместимость) —
   в `supply_plan` (ТЗ §7).
5. **Влияние цен** (prices) — `Σ по рейсам (норм. км × норма л/100км /
   100 × цена DIESEL на дату рейса)`; цена решения ANRE действует до
   следующего решения (forward-fill, как устроен сам ряд
   `FLT_FUEL_PRICES`).

## CLI

```bash
venv/bin/python modules/autopark/scripts/autopark_reports.py \
    --report all --date-from 2026-07-01 --date-to 2026-07-31 \
    --xlsx --pdf --out docs/Autopark/examples
```

* `--report` — `all` или один из `driver|truck|station|summary|management|prices`;
* `--xlsx` — Excel через openpyxl: лист на отчёт, шапка с названием и
  периодом, жирные заголовки на тёмной подложке, автоширина колонок,
  числовой формат `# ##0.00`, строка итогов, замороженная шапка (A5);
* `--pdf` — деловой HTML (встроенные стили, палитра `#132038`/`#1d4ed8`,
  A4 landscape) конвертируется установленным LibreOffice:
  `soffice --headless --convert-to pdf`. Путь ищется в PATH и в
  `/Applications/LibreOffice.app/...`. Промежуточный `.html` удаляется.

**Почему LibreOffice, а не reportlab**: soffice на машине установлен и
проверен вживую (примеры в `examples/` собраны им; кириллица и таблицы
проверены глазами через конвертацию страницы в JPEG). Запасной рендерер
означал бы второй, отличающийся внешний вид тех же отчётов — не нужен.
Тонкость: HTML-импорт Writer игнорирует часть CSS ячеек (фоны, границы),
поэтому шаблон дублирует их legacy-атрибутами (`border`, `bgcolor`,
`cellpadding`) — это осознанно, не архаика.

## Примеры (`docs/Autopark/examples/`)

Собраны с живой БД (2 года демо-операционки + реальный архив цен ANRE):

* все 6 отчётов × (xlsx + pdf) за июль 2026 —
  `autopark_<ключ>_2026-07-01_2026-07-31.*`;
* `summary` и `management` за YTD —
  `autopark_<ключ>_2026-01-01_2026-08-26.*`.

## Тесты

`tests/test_autopark.py`, блок «Task 5 (reports)»: контракт всех шести
отчётов, сортировка рейтинга, учёт лимита отклонений и исключение
DRAFT, forward-fill цены на дату рейса, round-trip XLSX (файл открывается
openpyxl-ом обратно), самодостаточность HTML. Всё на моках store — без
wallet и Oracle.
