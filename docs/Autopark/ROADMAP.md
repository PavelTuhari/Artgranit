# Автопарк — дорожная карта развития на 2 года

**Период:** сентябрь 2026 — август 2028
**Составлено:** 2026-08-26, по фактическому состоянию системы
**Стартовая точка:** модуль в бою на nufarul-контуре: 21 таблица FLT_, GPS-прослойка с симулятором,
реальный архив цен ANRE, 6 отчётов PDF/XLSX, телеграм-бот (ждёт токен), методичка логиста, 127 автотестов.

Принцип карты: **каждый квартал заканчивается тем, что руками делают меньше, чем в прошлом**.
Система началась с ручного ввода всего; через два года руками остаются только решения.

---

## Год 1 — от демонстрационного стенда к промышленной эксплуатации

### Q1 · сен–ноя 2026 — «Запуск в бой»

1. Договор с реальным GPS-провайдером и подключение через готовую прослойку
   (`/api/gps/ingest`, адаптер push или pull по контракту GPS_INTEGRATION.md).
   Пилот на одном бензовозе, симулятор остаётся эталоном для сравнения.
2. Телеграм-бот в эксплуатацию: токен BotFather, systemd-unit, белый список chat_id,
   мониторинг-пуши логисту.
3. Передача процесса логисту по методичке LOGIST_GUIDE.md: месяц двойного ведения
   (бумага + система), затем приёмка процесса владельцем.
4. Роли и права: логист / бухгалтер / руководство / только-чтение
   (сейчас единый вход портала). Журнал действий пользователя в FLT_EVENT_LOG.
5. Автозагрузка цен ANRE еженощно (cron поверх `anre.md/oil-get-table`)
   вместо ручного прогона скрипта.

**Выход квартала:** реальный трек хотя бы одного бензовоза в системе; логист работает сам.

### Q2 · дек 2026 – фев 2027 — «Данные без ручного ввода»

1. Интеграция учёта АЗС: остатки и реализация приходят из кассовой/учётной системы
   автоматически (API или ночной импорт) — суточный сток перестаёт вводиться руками.
2. Импорт накладных поставок из 1С/бухгалтерии, контроль дублей.
3. «Закрытие месяца» одним действием: расчётная ведомость зарплаты, выгрузка
   в бухгалтерию (XLSX / формат 1С), протокол расхождений с прошлым периодом.
4. Технический долг схемы: SOURCE='ANRE_FF' в CHECK-констрейнт цен, IS_FOREIGN
   для конечных пунктов, партиционирование FLT_GPS_TRACKS по месяцам.

**Выход квартала:** ни одной регулярной ручной загрузки данных.

### Q3 · мар–май 2027 — «Настоящие дороги»

1. Дорожная матрица расстояний: расчёт по дорожному графу (OSRM на своём сервере,
   офлайн), норматив утверждается логистом и версионируется — рейс хранит норматив,
   действовавший на его дату.
2. Планировщик: от жадной эвристики к VRP-решателю (OR-Tools): окна выгрузки,
   совместимость секций и продуктов, многодневный горизонт. Метрика: план системы
   против плана логиста по км и числу рейсов.
3. Прогноз реализации АЗС: сезонность, тренд, праздники — вместо простой
   среднесуточной. Точность прогноза (MAPE) как контролируемая метрика.

**Выход квартала:** нормативы совпадают с дорогами; планировщик выигрывает у ручного плана.

### Q4 · июн–авг 2027 — «Автоматический контроль»

1. Геозоны АЗС: авто-фиксация прибытия, убытия и стоянки под сливом по GPS;
   автоматические переводы статусов рейса.
2. Телематика бензовоза: датчики уровня по секциям / расходомер — фактический слив
   сверяется с накладной без участия человека.
3. Детекция сливов в пути: падение объёма вне геозоны АЗС → немедленный алерт в бот.
4. Фактический расход ДТ из CAN-шины вместо ручного ввода.

**Итог года 1 (KPI):** сток и факт — 100% автоматически; ≥95% рейсов с автофиксацией
прибытия; закрытие месяца ≤ 1 рабочего дня; все отклонения разобраны в 48 часов.

## Год 2 — масштаб и экосистема

### Q5 · сен–ноя 2027 — «Вся сеть»

1. Раскатка на реальную сеть Bemol: 46 АЗС, весь парк; миграция мастер-данных,
   нагрузочное тестирование на годовом объёме треков.
2. Несколько парков: подрядные перевозчики со своими тарифами, сравнение
   свой/наёмный транспорт по стоимости литро-километра.
3. Эксплуатационный контур: мониторинг, алертинг, регламент резервного копирования
   и восстановления (DR-учения раз в квартал).

### Q6 · дек 2027 – фев 2028 — «Мобильный водитель»

1. PWA-приложение водителя: задание на рейс, чек-лист приёмки, фото пломб,
   электронное подтверждение слива подписью оператора АЗС; офлайн-режим.
2. Электронная ТТН (e-CMR) для импортных рейсов Констанца–Кишинёв.
3. Push-уведомления водителю: изменение задания, следующая точка.

### Q7 · мар–май 2028 — «Экономика и аналитика»

1. BI-слой: себестоимость доставки литра по направлениям, АЗС, бензовозам; тренды.
2. Экономический эффект оптимизации в леях: факт против baseline «как ездили раньше».
3. Конструктор тарифов зарплаты: ставки за км по типам рейсов, ночные, простой —
   вместо констант 2,75/600 (текущие остаются профилем по умолчанию).
4. Отчёт по выбросам и евро-нормам парка — для тендеров и обновления флота.

### Q8 · июн–авг 2028 — «Экосистема»

1. EDI с пунктами загрузки (Кишинёв, МСПД, Констанца): заявка на загрузку
   формируется из плана поставок автоматически.
2. ML-детекция аномалий: систематический недолив по водителю/АЗС, нетипичный
   расход, подозрительные пары «маршрут-время».
3. Публичный API и кабинет заказчика перевозки (если появятся сторонние заказчики).
4. Аудит безопасности и пентест; фиксация процесса для внешнего аудита.

**Итог года 2 (KPI):** MAPE прогноза ≤ 8%; закрытие месяца ≤ 2 часов; потери
топлива к базе года 1 −30%; 100% рейсов с электронным подтверждением слива.

## Сквозные треки (весь период)

- **Качество данных:** ежемесячная сверка Oracle ↔ 1С ↔ АЗС; расхождение — инцидент.
- **Тесты:** ни один квартал не снижает покрытие (сейчас 127); интеграционные
  прогоны на живой БД перед каждой раскаткой.
- **Документация:** README, методичка и должностная обновляются в том же квартале,
  что и функциональность — иначе задача не закрыта.
- **Обучение:** после Q1 логист сам обучает сменщика; система знаний не завязана
  на одного человека.

## Что сознательно НЕ входит

- Продажа топлива на АЗС (кассовый контур) — отдельная система, интегрируемся, не поглощаем.
- Собственная навигация/картография для водителя — используется штатный навигатор.
- Блокчейн, «ИИ-агенты» и прочие технологии без измеримой пользы для литра доставленного топлива.
