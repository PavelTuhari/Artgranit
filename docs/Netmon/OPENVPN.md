# OpenVPN офиса: кто подключён и как выдать доступ

Через этот сервер идёт вся удалённая работа с офисной сетью — им же
подключён владелец, когда правит что-то из дома. До сих пор про него было
известно только «машина жива»; кто в сети и кому вообще выдан доступ, не
видел никто.

## Сервер

| Что | Значение |
|---|---|
| Машина | виртуальная машина **139** на PROXMOX3, Ubuntu 20.04 |
| Внутри сети | `192.168.0.200` |
| Снаружи | `93.115.136.18:1194` (UDP) |
| Версия | OpenVPN 2.4.12 |
| Файлы | `/etc/openvpn/server`, PKI — `easy-rsa` внутри |
| Доступ | SSH root, пароль в Keychain (запись `pve-openvpn`) |

Сетевого API у OpenVPN нет: состояние лежит в файлах, поэтому модуль ходит
по SSH и читает `openvpn-status.log` (кто в сети) и `pki/index.txt`
(кому выдан сертификат).

## Что видно на панели

Вкладка «OpenVPN» панели
https://nufarul.eminescu.md/UNA.md/orasldev/netmon:

* работает ли служба, время работы, версия;
* **кто в сети сейчас** — имя, адрес в туннеле, откуда подключён, сколько
  принято и отдано, с какого времени;
* **все выданные сертификаты** — действует или отозван, до какого числа,
  в сети ли прямо сейчас;
* форма выдачи нового доступа и кнопка отзыва.

## Выдать доступ

Ввести имя латиницей и нажать «Создать профиль». Дальше:

1. на сервере выпускается сертификат на 10 лет
   (`easyrsa build-client-full <имя> nopass`);
2. собирается готовый файл `<имя>.ovpn` — в него вшиты `ca.crt`,
   сертификат, закрытый ключ и `tls-crypt`, ничего донастраивать не нужно;
3. браузер скачивает файл, **на сервере копия профиля не остаётся**.

**Файл содержит закрытый ключ.** Передавать лично; не через общие папки,
не в переписке, не в репозиторий. Имя — латиница, цифры, точка, дефис и
подчёркивание, начинается с буквы, до 31 символа: имя подставляется в
команды `easy-rsa`, поэтому набор символов ограничен жёстко.

## Отозвать доступ

Кнопка «Отозвать» в таблице сертификатов: сертификат уходит в список
отзыва (`crl.pem`), список обновляется и копируется туда, откуда его читает
служба. Действующая сессия этого клиента разорвётся при следующем
переподключении, не мгновенно.

## Главное, что здесь надо знать

Выдано **36 действующих сертификатов** и 20 отозванных. Сеть плоская
(замечание аудита UPNET 2021, п. 2.1.8 —
[AUDIT_2021_REVIEW.md](AUDIT_2021_REVIEW.md), раздел 3), а конфигурация
содержит `push "redirect-gateway def1"`. Значит **каждый из 36 ключей
открывает всю офисную сеть целиком**: Oracle, гипервизор, рабочие станции.
Часть выдана в 2020 году, и кто из этих людей ещё работает — по файлам не
видно.

Что с этим делать, по порядку:

1. пройти по списку на вкладке и отозвать доступы тех, кто ушёл;
2. ограничить маршруты, которые сервер отдаёт клиенту, вместо выдачи всей
   сети;
3. дальше — сегментация (VLAN), это большая работа, см. раздел 5 разбора
   аудита.

## Мониторинг

Хост Zabbix `office-openvpn` («OpenVPN офиса»), группа
`Infrastructure Health`:

| Элемент | Зачем |
|---|---|
| `vpn.service.up` | ноль означает, что удалённой работы нет вовсе — ни SSH, ни бэк-офиса, ни базы |
| `vpn.clients.online` | сколько сотрудников в туннеле |
| `vpn.certs.valid` | рост без ведома администратора = выданный и забытый доступ во всю сеть |
| `vpn.certs.revoked` | для истории |

```bash
python modules/netmon/scripts/netmon_zabbix_storage.py --only vpn
```

## API

| Адрес | Что делает |
|---|---|
| `GET /UNA.md/orasldev/netmon/api/vpn` | состояние, клиенты, сертификаты |
| `POST /UNA.md/orasldev/netmon/api/vpn/clients` | выпустить сертификат (`{"name": "..."}`) |
| `GET …/api/vpn/clients/<имя>/profile` | скачать `.ovpn` (без кэширования) |
| `POST …/api/vpn/clients/<имя>/revoke` | отозвать |
