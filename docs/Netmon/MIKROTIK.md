## Выдать доступ

Форма «Выдать новый доступ L2TP/IPsec»: имя латиницей → «Создать учётку».

* **только L2TP/IPsec.** PPTP новым пользователям не выдаётся (см. ниже);
* профиль `l2tp-unisim` — тот же, в котором уже живут L2TP-учётки офиса;
* пароль — 16 букв и цифр, генерируется панелью и показывается один раз;
* в комментарии учётки — `netmon <дата> <кто выдал>`, такие учётки в
  таблице помечены «панель»;
* галочка «сразу сделать ссылку для получателя» — ссылка на 15 минут.

### Ссылка для получателя

Та же схема, что у OpenVPN ([../VPNGuide/README.md](../VPNGuide/README.md)),
тип `l2tp`. По ссылке — без входа в портал, на трёх языках:

* **Windows** — скрипт `office-vpn.ps1`: создаёт подключение «Office VPN» и
  сразу подключается. Запуск: правой кнопкой → «Выполнить с помощью
  PowerShell» или `powershell -ExecutionPolicy Bypass -File office-vpn.ps1`;
* **macOS и iPhone** — профиль `office-vpn.mobileconfig` с настроенным L2TP.
  Весь трафик идёт через офис (`OverridePrimary`): без этого macOS
  маршрутизирует только сеть выданного адреса, и `192.168.0.0/24` не
  открывается;
* **Android** — предупреждение: Android 12 и новее L2TP/IPsec не умеет,
  нужен OpenVPN;
* все значения для ручной настройки (сервер, логин, пароль, общий ключ,
  MS-CHAP v2) с кнопками копирования;
* JSON для ИИ-помощника и текстовая версия `instructions.md`.

Общий ключ IPsec читается с маршрутизатора **только** в момент создания
ссылки и сразу шифруется ключом из токена ссылки. В панели и в ответах API
его нет.

Какой ключ: L2TP-клиенты проходят через динамический пир `l2tp-in-server`,
который создаёт сам L2TP-сервер с `ipsec-secret` из его настроек. Статический
`l2tp_dynamic_peer` выключен. Проверено 06.10.2026 по живому L2TP-клиенту.

### Действия над существующей учёткой

| Кнопка | Что делает |
|---|---|
| «Новый пароль + ссылка» | новый пароль, старые ссылки этой учётки гаснут, новая ссылка. Учётка включается, если была выключена. Для учёток **только PPTP** недоступно: по ссылке выдаётся L2TP, а смена пароля оборвала бы работающий PPTP |
| «Выключить» | `disabled=yes`, текущая сессия рвётся, ссылки гаснут. **Не удаляет**: партнёрскую учётку после удаления не восстановить |
| «Включить» | обратно |

## Как модуль говорит с маршрутизатором — и почему так сложно

Пять ловушек, каждая найдена на живом маршрутизаторе, на каждую есть тест.

1. **Сломанный RSA-ключ хоста.** На RSA маршрутизатор рвёт соединение сразу
   после обмена ключами (`disconnect 3`), ещё до пароля. Второй ключ — DSA,
   а его убрали из OpenSSH 10 и из paramiko 4. Поэтому клиент — **paramiko 3.x**
   с явным отказом от RSA:

   ```bash
   /Users/pt/Projects.AI/Artgranit/venv/bin/pip install "paramiko>=3.4,<4"
   ```

   Лечится на маршрутизаторе `/ip ssh regenerate-host-key`; после этого
   подойдёт любой клиент.
2. **`print` выводит секреты.** В RouterOS v6 `/ppp secret print` и
   `/interface l2tp-server server print` показывают пароли и общий ключ
   открытым текстом. Модуль читает только через
   `:foreach … get` с явно перечисленными полями (`Session.rows`).
3. **Формат вывода.** Разделитель полей — символ `0x1F`, и RouterOS понимает
   только заглавную запись `\1F` (строчная — `syntax error`, ответ пустой).
   Комментарии бывают многострочными, поэтому каждая запись начинается
   маркером `0x1E`. `:put` обрезает управляющий символ в конце строки, поэтому
   в конце записи явный `~`.
4. **`:put [… print count-only]` печатает число дважды** (`205\r\n205`).
   Проверка «такой учётки ещё нет» отказывала бы на любом имени. Подсчёт —
   `:len [find …]` (`Session.count`).
5. **Python `.strip()` срезает `0x1C–0x1F`** как пробельные: терялась ровно
   первая запись любого списка. `run()` обрезает только пробелы и переводы
   строк.

API RouterOS (8728) на этом маршрутизаторе закрыт, REST в v6 нет — остаётся SSH.

## Zabbix

Хост `office-mikrotik` («MikroTik офиса — VPN»), группа `Infrastructure Health`:

| Элемент | Зачем |
|---|---|
| `mt.ppp.online` | VPN-сессий сейчас |
| `mt.ppp.pptp` | из них по PPTP — цель ноль |
| `mt.ppp.enabled` | включённых учёток — рост без ведома администратора = разбор |
| `mt.ppp.never` | включённых, ни разу не входивших |
| `mt.cpu` | загрузка процессора, триггер от 90 % |

```bash
python modules/netmon/scripts/netmon_zabbix_storage.py --only mikrotik
```

Первая отправка сразу после создания элементов уходит в отказ: Zabbix
подхватывает новые элементы при обновлении кэша конфигурации, раз в минуту.
Повторить через минуту.

## API (под входом, только внутренняя сеть)

| Адрес | Что делает |
|---|---|
| `GET …/netmon/api/mikrotik` | состояние, учётки (без паролей), сессии, выводы |
| `POST …/netmon/api/mikrotik/users` `{"name", "share_minutes", "share_lang"}` | новая учётка L2TP и ссылка |
| `POST …/netmon/api/mikrotik/users/<имя>/reset` `{"minutes", "lang"}` | новый пароль и ссылка |
| `POST …/netmon/api/mikrotik/users/<имя>/disable` | выключить, разорвать сессию, погасить ссылки |
| `POST …/netmon/api/mikrotik/users/<имя>/enable` | включить |
