## 1. Что нашлось в сети

Сканирование подсети офиса по портам умных устройств выявило **четыре
розетки Tuya / Smart Life**. Раньше они значились в инвентаре просто как
«сетевое оборудование» — по TTL их нельзя отличить от коммутатора.

| Адрес | Порт | Протокол | Состояние | Отклик |
|---|---|---|---|---|
| `192.168.0.203` | 6668 | Tuya 3.4 | в сети | ~77 мс |
| `192.168.0.206` | 6668 | Tuya 3.4 | в сети | ~81 мс |
| `192.168.0.207` | 6668 | Tuya 3.4 | в сети | ~1100 мс |
| `192.168.0.240` | 6668 | Tuya 3.4 | в сети | ~77 мс |

Все четыре заведены в реестр оборудования под кодами `PLUG-203`, `PLUG-206`,
`PLUG-207`, `PLUG-240`. **Помещения не заполнены** — их надо уточнить на
месте и вписать в паспорт.

У розетки `192.168.0.207` отклик 1100 мс против 77 мс у остальных: либо она
далеко от точки доступа, либо у неё слабый сигнал. Стоит посмотреть.

## 2. Почему нельзя управлять прямо сейчас

Розетки отвечают на порту 6668, но **молчат без ключа** — так устроен
локальный протокол Tuya. Каждое устройство шифрует обмен своим `local_key`;
без него команда «включить» просто отбрасывается.

Проверка широковещательных пакетов (их устройства шлют каждые несколько
секунд) показала заголовок `00006699` — это **протокол 3.4+**, где даже
объявление о себе зашифровано. В более старых версиях 3.1/3.3 оттуда можно
было прочитать `device_id`; здесь — нельзя.

Вывод: **ключи можно взять только из облака Tuya**. Это не ограничение
модуля, а защита протокола.

## 3. Как получить ключи (делается один раз)

1. Убедиться, что все четыре розетки добавлены в приложение **Smart Life**
   (или Tuya Smart) на телефоне — обычно они уже там, раз работают.
2. Зарегистрироваться на **https://iot.tuya.com** — аккаунт разработчика
   бесплатный.
3. Создать облачный проект: *Cloud → Development → Create Cloud Project*.
   Регион — **Central Europe**. Записать `Access ID` и `Access Secret`.
4. Привязать приложение: *Devices → Link App Account → Add App Account*,
   отсканировать QR-код из Smart Life (*Я → Центр управления → Сканировать*).
5. После привязки в *Devices → All Devices* появятся все розетки. Для
   каждой открыть карточку и скопировать **Device ID** и **Local Key**.

Если удобнее автоматически, из готового набора:

```bash
pip install tinytuya
python -m tinytuya wizard     # спросит Access ID, Secret, регион
```

Мастер сохранит `devices.json` со всеми `id` и `key` разом.

## 4. Куда положить ключи

Ключи хранятся **только в macOS Keychain**, по одной записи на розетку:

```bash
security add-generic-password \
  -s "tuya-192.168.0.203" \
  -a "<device_id>" \
  -w "<local_key>" \
  -l "Умная розетка 192.168.0.203" -U
```

Повторить для `.206`, `.207`, `.240`. После этого управление включается
само: панель перечитывает состояние и показывает кнопки.

Проверка из терминала:

```bash
cd /Users/pt/Projects.AI/Artgranit-netmon
venv/bin/python -c "
import sys; sys.path.insert(0,'.')
from modules.netmon import smartplug
for s in smartplug.all_status():
    print(s['ip'], 'управляется' if s.get('controllable') else s.get('reason'))"
```

## 5. Как управлять

### Через панель

Вкладка «Оборудование офиса» → карточка розетки → **Включить** / **Выключить**.
Каждое переключение записывается в журнал объекта: кто, когда и что сделал.

### Через API

| Метод | Адрес | Что делает |
|---|---|---|
| `GET` | `/UNA.md/orasldev/netmon/api/plugs` | состояние всех розеток: в сети, включена, мощность |
| `POST` | `/UNA.md/orasldev/netmon/api/plugs/<ip>/on` | включить |
| `POST` | `/UNA.md/orasldev/netmon/api/plugs/<ip>/off` | выключить |

Полные адреса для боевого контура:
- https://nufarul.eminescu.md/UNA.md/orasldev/netmon/api/plugs

Пример:

```bash
curl -b cookies.txt -X POST \
  https://nufarul.eminescu.md/UNA.md/orasldev/netmon/api/plugs/192.168.0.203/off
```

Ответ при отсутствии ключа — понятный отказ, а не молчание:

```json
{"success": false,
 "message": "нет ключа для 192.168.0.203: заведите запись Keychain tuya-192.168.0.203"}
```

### Важно про сеть

Розетки живут в `192.168.0.0/24`. Управление работает **только изнутри
офисной сети или через VPN93**. С боевого сервера `nufarul.eminescu.md`
(облако OCI) они недоступны — там панель покажет их как «недоступна».

## 6. Что делать дальше

1. **Уточнить, что подключено в каждую розетку** и вписать помещение в
   паспорт объекта: сейчас там стоит «уточнить».
2. Получить ключи по разделу 3 — без них это просто индикатор наличия.
3. Разобраться с откликом `192.168.0.207` (1100 мс против 77 мс).
4. Подумать о сценарии: если розетки питают что-то, что не нужно ночью,
   их выключение даёт ту же экономию, что и выключение компьютеров
   (см. раздел «Перерасход электроэнергии» в
   [MONITORING_SYSTEM.md](MONITORING_SYSTEM.md)).
