---

## 1. Зачем это отдельно от мониторинга сети

Zabbix отвечает на вопрос «жива ли железка в сети». Но кондиционер, котёл
и лифт в сеть не включены: их состояние знает только человек, который к ним
подошёл. При этом отказ кондиционера в серверной опаснее, чем падение
половины рабочих станций.

Поэтому здесь другой принцип: **паспорт объекта + журнал работ +
фотографии от сотрудников**, а не опрос по сети.

## 3. Регламент обслуживания

Сроки заложены в модуле (`modules/netmon/facility.py`, `SERVICE_RULES`):

| Тип | Вид работ | Периодичность |
|---|---|---|
| Кондиционер | чистка фильтров | **90 дней** |
| Кондиционер | заправка фреоном | **730 дней** (2 года) |
| Кондиционер | осмотр | 180 дней |
| Котёл | осмотр | 365 дней (перед сезоном) |
| Контроль доступа | осмотр | 180 дней |
| Лифт | осмотр | **30 дней** |
| Умная розетка | осмотр | 365 дней |

Панель сама считает, когда срок вышел: «просрочено на N дней» красным,
«через N дней» жёлтым при приближении, «работ не зафиксировано» — если по
объекту вообще нет записей.

## 4. Как вести журнал

### Через панель (обычный путь)

1. Вкладка «Оборудование офиса» → клик по строке → откроется паспорт.
2. Внизу «Добавить запись»: выбрать вид работ, описать что сделано, указать
   исполнителя → **Записать**.
3. Дата следующего обслуживания проставляется **автоматически** по
   регламенту: чистка фильтров — плюс 90 дней, фреон — плюс 2 года.

### Фотография состояния

В том же паспорте: поле выбора файла открывает **камеру телефона**
(`capture="environment"`), подпись — что на снимке. Снимок привязывается к
объекту и виден в его карточке с указанием, кто и когда снял.

Ограничения: форматы jpg, jpeg, png, heic, webp; не больше 12 МБ. Файлы
лежат на диске сервера (`modules/netmon/photos/`), в базе — только путь:
снимки занимают мегабайты, а Oracle нужен для связей, не для картинок.

### Через API

| Метод | Адрес | Что делает |
|---|---|---|
| `GET` | `…/netmon/api/facilities` | реестр со сроками обслуживания |
| `GET` | `…/netmon/api/facilities/<код>` | паспорт: журнал и фотографии |
| `POST` | `…/netmon/api/facilities/<код>/work` | добавить запись о работах |
| `POST` | `…/netmon/api/facilities/<код>/photo` | загрузить снимок |
| `GET` | `…/netmon/photo/<id>` | получить снимок |

Пример записи о чистке фильтров:

```bash
curl -b cookies.txt -X POST \
  https://nufarul.eminescu.md/UNA.md/orasldev/netmon/api/facilities/AC-01/work \
  -H 'Content-Type: application/json' \
  -d '{"work_kind":"filter","description":"Промыты фильтры, проверен дренаж","performer":"Иванов"}'
```

Виды работ: `filter` (чистка фильтров), `freon` (заправка фреоном),
`inspect` (осмотр), `repair` (ремонт), `install` (установка), `other`.

Загрузка снимка:

```bash
curl -b cookies.txt -X POST \
  https://nufarul.eminescu.md/UNA.md/orasldev/netmon/api/facilities/AC-01/photo \
  -F "photo=@filter.jpg" -F "caption=Фильтр после чистки"
```

## 5. Модель данных (Oracle, префикс `NMON_`)

| Таблица | Назначение |
|---|---|
| `NMON_FACILITIES` | паспорт объекта: код, тип, помещение, модель, серийный номер, адрес в сети, регламент, ответственный |
| `NMON_FAC_LOG` | журнал работ: вид, дата, исполнитель, описание, дата следующего раза, стоимость |
| `NMON_FAC_PHOTO` | снимки: путь к файлу, подпись, кто снял, когда, размер |

Текстовые колонки объявлены в **символьной семантике** (`VARCHAR2(N CHAR)`):
по умолчанию Oracle считает байты, и русский текст в короткие поля не влезает.

Установка: `python modules/netmon/scripts/netmon_deploy.py`.
Первичное заполнение: `python modules/netmon/scripts/netmon_facility_seed.py`
(повторный запуск безопасен — обновляет паспорта, журнал не трогает).
