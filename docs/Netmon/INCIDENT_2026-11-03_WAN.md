# Авария 03.11.2026: канал МТС, снаружи пропали VPN и OTRS

## Что случилось

Около 14:36 по Кишинёву у провайдера МТС перестал отвечать шлюз офиса
`93.115.136.17`. Кабель в порту маршрутизатора (`ether3_MTC`, 192.168.0.101)
был, адреса `93.115.136.18–22` на нём были, поэтому маршрутизатор сам увёл
весь исходящий трафик офиса на второй канал Orange (`195.22.241.126`).
Изнутри офиса всё работало.

Снаружи пропало всё, что проброшено только на адреса МТС:

| Что | Почему |
|---|---|
| OpenVPN | проброс UDP 1194 → 192.168.0.200 есть только на 93.115.136.18; в профилях `remote 93.115.136.18 1194` |
| L2TP / PPTP | у тех, кому выдан адрес 93.115.136.18; через Orange входы шли |
| otrs.una.md, xwiki.una.md, vpn.una.md | DNS указывает на 93.115.136.18 |
| ns1.una.md | 93.115.136.19 — только МТС; ns2 (внешний) зону берёт с него же |
| входящая почта mx2/mx3, mail.una.md, bonus.una.md, linktickets.una.md, порт 8080 | проброшены только на адреса МТС |

Проверено снаружи (с облачного сервера): 93.115.136.18 не отвечает ни на один
порт; 195.22.241.126 — 80/443 (OTRS отдаёт 200), L2TP/IPsec 500 и 1701, PPTP 1723.

## Почему не заметили

Шлюз Orange был в Zabbix, шлюза МТС — нет. Хосты `office-openvpn` и
`office-mikrotik` в Zabbix ни разу не получили данных (их заполняет скрипт,
расписания для него нет).

## Что поставлено на мониторинг (03.11.2026)

* Zabbix (`modules/netmon/scripts/netmon_zabbix_wan.py`): хост «GW MTC»
  (93.115.136.17, ICMP), триггеры «Канал интернета МТС не работает» (высокий)
  и «Офис без интернета: оба канала» (катастрофа); хост `otrs.una.md` —
  страница отвечает, сертификат, сценарий «OTRS» со страницей входа.
* Панель netmon, раздел MikroTik: каналы, жив ли шлюз, и какие сервисы
  проброшены только на канал — при аварии это первый вывод на странице.

Ограничение: всё это проверяется изнутри офиса. Изнутри оба внешних адреса
отвечают (маршрутизатор отдаёт их сам), поэтому «снаружи» видно только по
шлюзам провайдеров. Настоящая проверка снаружи требует точки вне офиса.

## Что требует решения владельца

1. Звонок в МТС — авария у провайдера.
2. Проброс OpenVPN (UDP 1194 → 192.168.0.200) на адрес Orange — правило на
   MikroTik рядом с существующим «openvpnfinal».
3. Профили OpenVPN — второй адрес `remote 195.22.241.126 1194`
   (клиент OpenVPN переходит на него сам).
4. Долгосрочно: важные сервисы — на оба канала; DNS — с адресами обоих каналов
   или с коротким временем жизни записей; ns1 — доступен и через Orange.
5. Проверка снаружи: расписание сбора на облачном сервере.
