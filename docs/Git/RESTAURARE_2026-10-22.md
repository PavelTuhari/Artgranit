# Восстановление 22.10.2026: что потерялось при слиянии 19.10 и как вернули

Владелец 22.10.2026: **«всё должно быть последней версии доработки, ориентируйся по
дате, когда делали; всё, что делали, не должно пропадать»**.

## Ошибка (моя, 19.10)

При консолидации (`GIT_CONSOLIDARE_2026-10-19.md`) конфликтные файлы решались
скриптом политики «код — сторона `main`». Скрипт брал **файл `main` целиком**
(стадия `:2:`), а не только конфликтные блоки. Поэтому пропали и те куски веток,
которые git слил бы сам, без конфликта. Плюс в конфликтных блоках выбор делался
«`main` всегда новее» — без сверки дат.

Хуже: 19.10 `main` был выкачен на серверы. На nufarul и облаке это **убрало с живого
сайта** две вещи, которые там работали до выкатки (проверено по резервным копиям
`~/artgranit_backup_before_main_2026-10-19.tgz`):

- боковую панель категорий в каталоге (требование владельца, 30.08);
- быстрый поиск через Oracle Text (`_one_word`, 28.08).

## Как нашли

1. По каждому слиянию — файлы, менявшиеся и в ветке, и в `main`; дата последней
   правки с каждой стороны; строки, добавленные веткой и отсутствующие в итоге.
2. Для каждого файла — честный 3-way (`git merge-file`, база / `main` / ветка),
   конфликты на стороне `main`; разница с тем, что я закоммитил = **куски, потерянные
   без конфликта**. Итог: 29 файлов; в документах — только добавления (ничего не стёрто),
   в e-Factura/partner потерь нет (там `main` новее), реальные потери — в витрине и
   планограммах.

## Правило (добавлено в CLAUDE.md правило №6 и AGENTS.md)

**При конфликте слияния никогда не брать файл одной стороны целиком.** Только
3-way по блокам (`git merge-file`): не конфликтующие куски обеих сторон остаются;
каждый конфликтный блок решается по дате коммитов, которые его меняли, и по смыслу.
После — поиск вызовов функций, чьи определения остались в отброшенных блоках, и
сверка с резервной копией сервера, что ничего работавшего не пропало.
