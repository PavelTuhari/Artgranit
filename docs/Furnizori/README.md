# Работа с поставщиками (`furnizori`)

Изолированный модуль Artgranit поверх общего ядра. Создан `scripts/new_module.py`.

| Что | Где |
|---|---|
| URL | `/UNA.md/orasldev/furnizori` |
| Пакет | `modules/furnizori/` |
| Oracle-префикс | `FRZ_` (DDL в `modules/furnizori/sql/`, установщик `modules/furnizori/scripts/furnizori_deploy.py`) |
| Тесты | `tests/test_furnizori.py` (изоляция + правила) |
| Ветка / worktree | `feat/furnizori` / `../Artgranit-furnizori` |

## Зачем модуль

Переписка с поставщиками была файлами на диске у одного человека: кому что
отправили, ответили ли, какая версия таблицы ушла — нигде не зафиксировано.
Модуль превращает письмо в **документ портала**: карточка + вложения в базе,
с отметкой об отправке и ответе.

Первый повод — письма об исправлении наименований со смешанными алфавитами
(латиница + кириллица внутри слова). 386 позиций по девяти поставщикам,
подготовлены в BIRO26 (аудит гомоглифов).

## Модель данных

```
TMS_ORG_IMPSRC (реестр источников, ERP OfficePlus)
     └── FRZ_LETTER        письмо = документ          1:N
              └── FRZ_LETTER_FILE  .eml / .xlsx в BLOB  1:N
```

**Почему не `TMDB_DOCS`.** Это регистр *бухгалтерских* документов: сквозная
нумерация `NRMANUAL`, проводки, НДС. У письма нет суммы, оно не попадает в
баланс, а его вставка сдвинула бы нумерацию счетов. Переписке там не место.

**Почему связь по коду, а не внешним ключом.** `FRZ_*` лежат в базе портала
una.md (OCI, wallet), а `TMS_ORG_IMPSRC` — в боевой ERP OfficePlus (Oracle 11g,
`orange.una.md`). Это две разные базы. В ERP ходят только через
`models/biro26_db.py` — thick-режим переключает *весь процесс* и оборвал бы
облачное подключение остальных модулей портала. Поэтому справочник поставщиков
читается оттуда отдельным вызовом, а в письме хранится `SRC_CODE`.

### Жизненный цикл письма

`NOU` (черновик) → `TRIMIS` (отправлено) → `RASPUNS` (есть ответ) → `INCHIS`.
Даты `SENT_AT` и `ANSWER_AT` проставляются сами при смене статуса — оператору
не надо вводить их руками и незачем ошибаться.

## API

| Метод | Адрес | Что делает |
|---|---|---|
| `GET` | `/api/letters?status=` | список писем с числом вложений |
| `POST` | `/api/letters` | создать письмо |
| `PATCH` | `/api/letters/<id>` | сменить статус / адрес / заметку |
| `DELETE` | `/api/letters/<id>` | удалить письмо и его вложения |
| `GET/POST` | `/api/letters/<id>/files` | список / загрузка вложения |
| `GET` | `/api/files/<id>/download` | скачать вложение |
| `DELETE` | `/api/files/<id>` | удалить вложение |
| `GET` | `/api/reference` | поставщики, статусы, типы |

Все маршруты закрыты `AuthController`. Изменяемые поля письма — белым списком
в `store._EDITABLE`: через API нельзя переписать произвольную колонку.

### Что не принимается во вложения и почему

`rules.ALLOWED_EXT` — только данные (`eml, xlsx, xls, csv, pdf, docx, png, jpg,
jpeg, zip`), до 25 МБ. `.html` и `.svg` отклоняются намеренно: файл потом
отдаётся обратно в браузер с того же домена, и скрипт внутри выполнился бы в
сессии оператора. По той же причине отдача идёт с `Content-Disposition:
attachment` и `X-Content-Type-Options: nosniff`, а имя чистится
`rules.safe_filename()` — иначе через перевод строки в имени можно подделать
HTTP-заголовок.

## Загрузка готовых писем

```bash
python modules/furnizori/scripts/furnizori_load_letters.py \
       --dir /Users/pt/Projects.AI/BIRO26/Scrisori_furnizori
```

Тема, адрес и число позиций читаются из самого `.eml` — чтобы карточка не
разошлась с тем, что реально отправлено. Повторный запуск не плодит дублей:
письмо узнаётся по SHA-256 вложенного `.eml`.

## Журнал изменений

- **создание каркаса** — worktree, ветка, пакет, тесты изоляции, документация.
- **письма поставщикам** — таблицы `FRZ_LETTER` / `FRZ_LETTER_FILE`, API,
  интерфейс со сменой статуса и вложениями, загрузчик `.eml`.
  Загружено 9 писем (386 позиций), у каждого `.eml` + `.xlsx`.
  Проверка: `pytest tests/test_furnizori.py` — 12 зелёных; `.eml` из базы
  разбирается обратно и вложенный `.xlsx` цел.

### Грабли

`deploy_oracle_objects.py` режет SQL по `;`, **не различая комментарии**.
Точка с запятой внутри `--` комментария разрывает `CREATE TABLE` на две
невалидные части (`ORA-00900`, дальше каскад `ORA-00942`). В `sql/*.sql`
этого модуля точек с запятой в комментариях нет — и добавлять нельзя.
