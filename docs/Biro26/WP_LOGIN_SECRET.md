# Секретный вход в админку WordPress (officeplus.md)

**Дата:** 01.09.2026
**Задача владельца:** «перенести вход на нестандартный адрес — добавь ещё и
хештег, таким образом если линк не знаешь, то уже вообще на окно логина не
попадёшь».

## Ссылка для входа

```
https://officeplus.md/op-intrare-6b89dc08
```

Открыть её один раз — сервер выдаёт cookie на 12 часов и переводит на обычную
форму входа. Дальше вход как всегда: `officeplus` / пароль.

**Сохранить эту ссылку в менеджере паролей.** Потеряется — вход закрыт для
всех, включая владельца; восстановление только правкой конфига на сервере
(файл указан ниже).

## Про «хештег»

Хештег (`#...`) браузер на сервер **не отправляет** — это часть только для
самой страницы. Проверить по нему нельзя ничего. Поэтому секрет сделан
частью адреса: результат тот же — не знаешь ссылку, не видишь форму, — но
работает по-настоящему.

## Что происходит на сервере

| Кто | Что видит |
|---|---|
| Бот / чужой на `/wp-login.php` | **404** — страницы просто нет |
| Бот / чужой на `/wp-admin/` | **404** |
| Пришёл по секретной ссылке | cookie `opgate`, дальше форма как обычно |
| Витрина (`admin-ajax.php`) | работает, **не закрыта** — иначе сломались бы формы сайта |

## Файлы

| Где | Что |
|---|---|
| `deploy/officeplus/wp-login-gate.inc` | исходник (репозиторий) |
| `/etc/nginx/conf.d/officeplus-wp-gate.inc` | на 92.5.130.1 |
| `/etc/nginx/snippets/wp-harden.conf` | сюда добавлена одна строка проверки cookie |

Отдельный файл, а не правка общего конфига — по CLAUDE.md, правило №2.
Проверку cookie для `wp-login.php` пришлось встроить в `wp-harden.conf`, а
не описывать заново: nginx не допускает два блока на один адрес, а в
существующем уже стоял лимит попыток (`limit_req zone=wplogin`) — его надо
было сохранить. Теперь защиты две: адрес не угадать, и даже с адресом
перебор ограничен.

Админка живёт на **92.5.130.1** (не в офисе): проверено сравнением md5
страницы `wp-login.php` с ответом этого хоста.

## Откат

```bash
ssh -i /Users/pt/Keys/oracle-ecommerce-web ubuntu@92.5.130.1 'sudo rm /etc/nginx/conf.d/officeplus-wp-gate.inc && sudo cp /root/wp-harden.conf.before-gate /etc/nginx/snippets/wp-harden.conf && sudo nginx -t && sudo systemctl reload nginx'
```

## Смена секрета

Заменить путь и токен в обоих местах (`officeplus-wp-gate.inc` и строку
`$cookie_opgate` в `wp-harden.conf`) — значения должны совпадать, — затем
`sudo nginx -t && sudo systemctl reload nginx`.
