**Кому:** ИИ-модели / команде, отвечающей за сайт officeplus.md (репозиторий `Artgranit`).
**От:** импорт-команды (BIRO26 / OfficePlus).
**Дата:** 2026-08-15.
**Приоритет:** первая проблема — высокий (ломает эндпоинты в продакшене), вторая —
средняя (2 324 товара без картинок в каталоге).

> Правило проекта: любые сообщения и комментарии **в коде для БД** (PL/SQL, SQL,
> `DBMS_OUTPUT`) — только RO/EN в формате `RO: <text> / EN: <text>`, без русского.
> Идентификаторы — на английском. Этот документ и переписка — по-русски.

## 0. Краткая суть

1. **На сервере лежат файлы из разных коммитов.** Это уже сломало один эндпоинт
   (`/api/biro26/pt/sources` отдаёт 500 вместо 401) и не даёт заработать исправлению

2. **Картинки impreso.md не показываются**, потому что сайт-источник вообще не имеет
   HTTPS. Исправление (прокси) уже написано и лежит в `main`, но на сервер не попало.

## 1. Проблема A: рассинхрон деплоя (корневая)

### 1.1. Доказательства с живого сервера

```bash
curl -s -o /dev/null -w "%{http_code}  %{url_effective}\n" \
  https://officeplus.md/api/biro26/pt/help \
  https://officeplus.md/api/biro26/connection/test \
  https://officeplus.md/api/biro26/pt/sources \
  https://officeplus.md/api/biro26/img
```

Что получаем сейчас:

| Эндпоинт | Факт | Ожидание | Вывод |
|---|---|---|---|
| `/api/biro26/pt/help` | **401** | 401 | ✅ норма (запрос без авторизации) |
| `/api/biro26/connection/test` | **401** | 401 | ✅ норма |
| `/api/biro26/pt/sources` | **500** | 401 | ❌ падает **до** проверки авторизации |
| `/api/biro26/img` | **404** | 200 | ❌ маршрута нет в задеплоенном `app.py` |

404 отдаёт именно Flask (страница Werkzeug, 207 байт), а не nginx — то есть запрос
доходит до приложения, и приложение просто не знает такого маршрута.

### 1.2. Почему 500, а не 401 — и что это доказывает

Маршруты объявлены так:

```python
@app.route('/api/biro26/pt/sources', methods=['GET'])
def api_biro26_pt_sources():
    return _b26(Biro26Controller.pt_sources)
```

`_b26` — это обёртка, которая **внутри себя** проверяет авторизацию:

```python
def _b26(fn):
    g = _biro26_api_guard()
    if g is not None:
        return g          # <- 401 отдаётся здесь
    return jsonify(fn())
```

Python вычисляет аргумент `Biro26Controller.pt_sources` **до** входа в `_b26`. Если
метода в контроллере нет — `AttributeError` вылетает раньше, чем отработает guard,
и Flask отдаёт 500 вместо 401.

**Отсюда однозначный вывод:** на сервере `app.py` содержит маршрут `pt/sources`
(коммит `9ff2e9b`), а `controllers/biro26_controller.py` — **не содержит** метода
`pt_sources` из того же коммита. Два файла из разных версий.

И одновременно `app.py` **не** содержит маршрут `/api/biro26/img` (коммит `e017097`),
то есть сам `app.py` старше последнего коммита.

### 1.3. Что нужно сделать

Полный деплой ветки `main`, а не выборочное копирование файлов:

```bash
cd /opt/artgranit
git status                      # RO: verificati modificarile locale / EN: check local changes
git stash                       # только если git status показал изменения
git fetch origin
git reset --hard origin/main
sudo systemctl restart artgranit
```

`git reset --hard` **удаляет** незакоммиченные правки на сервере — если они там есть и
нужны, сначала `git stash`, а после деплоя разобраться с ними отдельно.

### 1.4. Проверка после рестарта

```bash
# RO: trebuie 401 (nu 500) / EN: must be 401, not 500
curl -s -o /dev/null -w "%{http_code}\n" https://officeplus.md/api/biro26/pt/sources

# RO: trebuie 200 image/jpeg / EN: must be 200 image/jpeg
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" \
  "https://officeplus.md/api/biro26/img?u=http%3A%2F%2Fwww.impreso.md%2Fproduct%2F9171%2Fimage-1B.jpg"
```

### 1.4a. Полная проверка: сломан ровно один эндпоинт

Чтобы вам не искать вслепую, мы уже прогнали **все 73 GET-маршрута** `/api/biro26/*`
из `app.py` по живому серверу. Результат:

| Код | Сколько | Что это |
|---|---|---|
| 401 | 55 | ✅ норма — защищённые эндпоинты, запрос без авторизации |
| 200 | 15 | ✅ норма — публичные эндпоинты |
| **500** | **1** | ❌ `/api/biro26/pt/sources` — рассинхрон (см. §1.2) |
| **404** | **1** | ❌ `/api/biro26/img` — маршрута нет в задеплоенном `app.py` |
| 000 | 1 | `/api/biro26/site/config` — не уложился в 12 с; при повторе **200 за 4.7 с** |

То есть **других жертв рассинхрона нет** — ровно те два, что мы нашли. После полного
деплоя оба должны стать 401 и 200 соответственно.

Отдельно обратите внимание на `/api/biro26/site/config`: **4.7 секунды** на ответ. Это не
связано с нашей задачей, но для эндпоинта конфигурации сайта — очень много, и он,
судя по названию, вызывается на каждой странице. Стоит посмотреть.

Скрипт проверки, если захотите повторить после деплоя:

```bash
# RO: extrage rutele GET si le verifica / EN: extract GET routes and probe them
python3 - <<'EOF' > /tmp/routes.txt
import re, io
s = io.open('app.py', encoding='utf-8').read()
r = re.findall(r"@app\.route\('(/api/biro26/[^']*)'(?:,\s*methods=\[([^\]]*)\])?\)", s)
print("\n".join(sorted({p for p, m in r if '<' not in p and 'GET' in (m or "'GET'").upper()})))
EOF

while read -r p; do
  printf '%s %s\n' "$(curl -s -o /dev/null -w '%{http_code}' --max-time 20 "https://officeplus.md$p")" "$p"
done < /tmp/routes.txt | sort | grep -v '^401\|^200'
```

Пустой вывод = всё в порядке.

### 1.5. Просьба: сделать так, чтобы это не повторилось

Рассинхрон файлов не даёт о себе знать, пока кто-то не вызовет конкретный эндпоинт.
Два предложения, оба дешёвые:

**а) Health-эндпоинт с версией.** Публичный (или под guard) `GET /api/biro26/health`,
возвращающий:

```json
{"commit": "e017097", "branch": "main", "dirty": false,
 "started_at": "2026-08-15T10:00:00Z", "routes": 412}
```

Коммит брать из `git rev-parse --short HEAD` при старте приложения (или из переменной
окружения, которую проставляет деплой). Тогда «что реально крутится на сервере» —
вопрос одного `curl`, а не расследования на полдня, как в этот раз.

**б) Smoke-тест маршрутов при старте.** Пройтись по `app.url_map` и проверить, что для
каждого правила существует его view-функция и все атрибуты контроллеров, на которые
она ссылается, резолвятся. Такой рассинхрон упал бы на старте с внятной ошибкой в логе,
а не 500-й в проде.

Если у деплоя есть причина копировать файлы выборочно (например, чтобы не трогать
конфиги) — расскажите, какая: тогда подберём вариант, где список файлов не надо
поддерживать руками.

## 2. Проблема B: картинки impreso.md

### 2.1. Что произошло

Импорт-команда загрузила каталог impreso.md: **2 662 товара**, все URL картинок
записаны в БД и **корректны**. В каталоге картинки не появляются.

Причина не в данных: **у impreso.md вообще нет HTTPS**.

```
200  image/jpeg  47 693 байт   <-  http://www.impreso.md/product/5634/image-1B.jpg
000  соединение не установлено <-  https://www.impreso.md/product/5634/image-1B.jpg
```

Это не ошибка сертификата — на 443 порту ничего не слушает. Магазин работает по HTTPS,
браузер блокирует `<img src="http://...">` на HTTPS-странице как mixed content. В БД всё
правильно, не видно только в браузере.

### 2.2. Что уже сделано (лежит в `main`, коммит `e017097`)

**`models/biro26_imgproxy.py`** — новый файл:

- `proxy_url(url)` — возвращает URL для отдачи в браузер: через прокси, если нужно,
  иначе без изменений;
- `rewrite_rows(rows, "IMAGE")` — применяет это к списку словарей результата SQL;
- `fetch(url)` — серверная загрузка картинки.

**Маршрут в `app.py`:** `GET /api/biro26/img?u=<url-encoded>` — тянет по HTTP и отдаёт
по HTTPS с `Cache-Control: public, max-age=86400`.

**Подстановка сделана централизованно, в `models/biro26_oracle_store.py`,** в трёх
местах, где рождается поле картинки: список товаров (витрина и бэк-офис), карточка
товара, список цен. Шаблоны и `site.js` не трогали — они по-прежнему получают готовое
поле `image`.

### 2.3. Безопасность — не ослаблять при доработках

Прокси, который скачивает произвольный присланный URL, — это SSRF-дыра: через него можно
запрашивать внутренние адреса от имени нашего сервера. Защиты, которые **должны
остаться**:

| Защита | Зачем |
|---|---|
| белый список хостов (`ALLOWED_HOSTS`) | сейчас только `impreso.md`, `www.impreso.md` |
| редиректы не выполняются | редирект мог бы увести запрос за пределы белого списка |
| только ответы `image/*` | чтобы не отдавать HTML/JSON с чужого сервера |
| лимит 8 МБ | картинка товара весит меньше 1 МБ |

Проверено локально: `http://evil.example.com/x.jpg` и `http://127.0.0.1:8080/admin`
отклоняются, реальная загрузка с impreso отдаёт 47 693 байта `image/jpeg`.

**Добавлять новый источник — только через `ALLOWED_HOSTS`,** и только если у источника
действительно нет HTTPS. Если HTTPS есть — прокси не нужен, `needs_proxy()` вернёт
`False` и URL пойдёт напрямую.

### 2.4. Что нужно от вас

1. Задеплоить (см. §1.3). Проверить, что `models/biro26_imgproxy.py` **реально попал на
   сервер** — это новый файл; при выборочном копировании его легко потерять, и тогда
   `biro26_oracle_store.py` упадёт с `ImportError` на первом же запросе каталога.
2. Проверить страницу:
   `https://officeplus.md/catalog?grupa=Cartus+Toner&categorie=Cartus+Monochrom`
   — там 525 товаров, у всех должны появиться картинки.
3. Если после деплоя картинки всё ещё не видны — значит, страница берёт поле картинки
   не через те три места в `biro26_oracle_store.py`, которые мы покрыли. Тогда пришлите,
   какой эндпоинт реально вызывает каталог (видно в DevTools → Network), и мы допишем.

## 3. Проблема C: заглушка «нет изображения» (уже исправлено в БД, нужна защита в коде)

У 319 товаров impreso в качестве картинки стоял
`http://www.impreso.md/img/product/noimage_b.jpg` — это **заглушка сайта-источника**,
но физически настоящий JPEG на 57 КБ. Импорт принял её за нормальную картинку, и товары
выглядели как «с фото».

Это хуже, чем отсутствие картинки: интерфейс не знает, что фото нет, и не может показать
плейсхолдер, а фильтр «товары без фото» такие карточки не найдёт.

В БД уже вычищено (проставлен `NULL`). **Просьба к вам:** если где-то в коде сайта или
в вашей части импорта URL картинки подставляется/сохраняется, добавьте отсев по
подстроке `noimage` — такие заглушки есть почти у каждого сайта-источника, названия
разные (`noimage`, `no-image`, `placeholder`, `default.jpg`).

Текущее состояние карточек impreso:
