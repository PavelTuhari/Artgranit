# Инцидент 01.09.2026: порог рассрочки 1500 лей стёрт выкладкой

## Что случилось

Порог `CREDIT_MIN_ORDER` (красное условие и блокировка кнопок
кредитования при заказе меньше 1500 лей; правило владельца от 18.08)
исчез с работающих контуров.

## Причина

Логика жила в общем `app.py`. Выкладка tar-ом поверх дерева, собранного
из более ранней точки ветки, перезаписала файл целиком — вместе с
порогом. Ни git, ни тесты этого не поймали: в точке сборки порога ещё не
было, значит и терять было «нечего».

## Восстановление

- Реализация вынесена в **отдельный файл** `models/biro26_credit_min.py`
  (коммит `c878dd4`); в `app.py` — вызов в одну строку.
- Порог настраивается через `YBIRO_SETTINGS.CREDIT_MIN_ORDER`, по
  умолчанию 1500; при недоступной БД — 1500, а не ноль (ноль означал бы
  «рассрочка на любую сумму»).
- Разнесено в обе линии: `main` (cherry-pick) и `merge-autopark`
  (слияние) — теперь ни одна выкладка любой из веток порог не унесёт.
- Четыре теста отдельным файлом `tests/test_credit_min.py`, включая
  «логика не в общем файле».

## Чтобы не повторилось

Правила №1–3 в `CLAUDE.md` (репозитория и проекта BIRO26): важная логика
не в общих файлах; каждое изменение — с md-документом; перед выкладкой
tar-ом сверять коммит сервера со своей точкой.
