Перенос на officeplus.una.md

Магазин переезжает на площадку в офисной сети. Что и в каком порядке менять, чтобы не потерять платежи и выдачу счетов из ERP.

92.5.130.1 ──▶ 93.115.136.18 · внутр. 192.168.0.148

Куда именно переезжаем

Целевая площадка — 93.115.136.18, внешний адрес офисной сети; за NAT стоит 192.168.0.148. Определено сверкой: страница, которую отдаёт officeplus.una.md, побайтово совпадает с той, что отдаёт .148.

officeplus.una.md уже готов

Ведёт на новую площадку, отдаёт магазин, сертификат действителен — браузер открывает без предупреждений. Здесь делать нечего.

officeplus.md ещё на старом адресе

Все записи в зоне на nic.md показывают на 92.5.130.1. Именно их и нужно переключить — это та таблица, что вы прислали.

Про mail: MX у домена нет

У officeplus.md нет ни одной MX-записи, а порт 25 закрыт на обоих адресах. Входящей почты на домене нет, приложение шлёт письма через Gmail. Запись mail сейчас ничего не обслуживает — её можно оставить как есть.

Порядок работ

Сложность одна: сертификат для officeplus.md нельзя выпустить на новой площадке, пока имя туда не показывает, а до выпуска браузер будет ругаться. Поэтому шаги 1–2 готовятся заранее, а 3 и 4 идут подряд, без паузы.

  1. Подготовить vhost на новой площадке

    192.168.0.148 · nginx

    Сейчас на этой машине имя officeplus.md попадает на посторонний сайт — отдаётся чужая страница с пустым <title>, не магазин. Нужно добавить имя туда же, где обслуживается officeplus.una.md:

    server_name officeplus.una.md officeplus.md www.officeplus.md;

sudo nginx -t && sudo systemctl reload nginx

  2. Снизить TTL на nic.md

    зона officeplus.md · панель nic.md

    За сутки поменять «Auto» на 300 секунд у записей @ и www. Тогда и переключение, и откат разойдутся за пять минут, а не за сутки.

  3. Переключить A-записи

    зона officeplus.md · панель nic.md

    По таблице выше: 92.5.130.1 → 93.115.136.18.

    dig +short officeplus.md A
# должно стать 93.115.136.18

    С этого момента и до шага 4 сайт по HTTPS будет ругаться на сертификат — действующий выписан на una.md и officeplus.una.md, но не на officeplus.md.

  4. Сразу выпустить сертификат

    192.168.0.148 · certbot

    Не откладывать: делать следом за шагом 3, как только DNS разошёлся.

    sudo certbot --nginx \
     -d officeplus.una.md -d officeplus.md -d www.officeplus.md

sudo certbot certificates

    Проверка ходом Let's Encrypt идёт по HTTP на порт 80 снаружи — убедиться, что он проброшен на .148 и не перехвачен редиректом.

  5. Сделать officeplus.una.md главным

    192.168.0.148 · nginx

    Оба имени ведут на одну машину, но поисковику и платёжному шлюзу нужен один канонический адрес:

    server {
    listen 443 ssl;
    server_name officeplus.md www.officeplus.md;
    return 301 https://officeplus.una.md$request_uri;
}

    Одно исключение

    Путь /api/biro26/ редиректить нельзя: по нему Oracle 11g ходит простым HTTP и редиректов не понимает. Оставить его рабочим на обоих именах, пока не сделан шаг 8.

  6. Переключить WordPress

    192.168.0.148 · база WordPress

    Двух настроек мало — адрес сидит и внутри контента, в ссылках и картинках.

    UPDATE wp_options SET option_value='https://officeplus.una.md'
 WHERE option_name IN ('siteurl','home');

wp search-replace 'https://officeplus.md' 'https://officeplus.una.md' \
   --all-tables --skip-columns=guid

  7. Переключить платежи

    Oracle · YBIRO_SETTINGS.NOTIFY_PUBLIC_BASE

    Из этой настройки строятся адреса возврата и подтверждения для MAIB и MIA. Сейчас там https://officeplus.md. Не сменить — клиент после оплаты вернётся на старый адрес, а подтверждение может не дойти.

    SELECT SVAL FROM YBIRO_SETTINGS WHERE SKEY='NOTIFY_PUBLIC_BASE';

BEGIN y_ai_BIRO26.set_setting(
  'NOTIFY_PUBLIC_BASE', 'https://officeplus.una.md'); END;
/

    Отдельно предупредить MAIB

    Банк принимает возвраты только на адреса, зарегистрированные у него для мерчанта. Смена настройки на нашей стороне этого не делает — нужно письмо в MAIB, иначе оплата картой перестанет проходить. То же по MIA.

  8. Пересобрать пакет Oracle

    Oracle · Y_AI_BIRO26

    Адрес зашит прямо в тексте пакета, в двух местах — строки 472 и 618 (gen_conturi и gen_conturi_pr). Настройкой не меняется.

    v_url := 'http://officeplus.una.md/api/biro26/gen-docs-by-nr/'

    Править в sql/biro26/04_y_ai_biro26.sql и накатывать заново. Оставить именно http: у Oracle 11g нет TLS-кошелька, а эндпоинт защищён ключом API.

  9. Обновить внешнее

    поиск, реклама, документы

    • Google Search Console — добавить ресурс и отправить смену адреса.
    • Шаблоны писем и подписи, если домен указан в них.
    • Соцсети, Google Business, визитки, бланки счетов.
    • Telegram и WhatsApp: ссылки строятся из той же NOTIFY_PUBLIC_BASE — отдельной правки не нужно.

Проверка после переключения

  • dig +short officeplus.md → 93.115.136.18
  • Витрина открывается: https://officeplus.una.md/catalog → 200
  • Замок без предупреждений на обоих именах
  • Старое имя ведёт на новое: curl -I https://officeplus.md/catalog → 301
  • Бэк-офис пускает: https://officeplus.una.md/login
  • Админка WordPress открывается и не уводит на старый адрес
  • Пробная оплата картой проходит и возвращает на новый адрес
  • Счёт из ERP генерируется: y_ai_BIRO26.gen_conturi отдаёт файл
  • Письмо клиенту приходит со ссылками на новый домен

Если что-то пошло не так

Откат — вернуть A-записи на 92.5.130.1 и NOTIFY_PUBLIC_BASE на прежнее значение. Старая площадка продолжает работать всё это время и остаётся полностью рабочей копией, так что откат мгновенный по сути — вопрос только в TTL.

Поэтому шаг 2 важнее, чем кажется: с TTL 300 откат разойдётся за пять минут, с «Auto» может занять сутки.

Что будет со старой площадкой 92.5.130.1

Пока на неё не показывает ни одно имя, она просто простаивает — код, база WordPress и настройки остаются на месте. Это удобный запасной вариант на первое время: если на новой площадке всплывёт проблема, возврат делается одной правкой DNS. Отключать её стоит не раньше, чем новый адрес отработает без замечаний хотя бы неделю.

Состояние DNS и обеих площадок проверено 18 августа 2026. Перед работами сверить заново: dig +short officeplus.md и dig +short officeplus.una.md.
