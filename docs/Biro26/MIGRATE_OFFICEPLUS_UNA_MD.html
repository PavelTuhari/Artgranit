Перенос на officeplus.una.md

Что и в каком порядке менять, чтобы магазин переехал на новое имя, не потеряв платежи, письма и выдачу счетов из ERP.

officeplus.md ──▶ officeplus.una.md · сервер 92.5.130.1

Что уже сделано, а что нет

officeplus.md уже на новом хостинге

Публичный DNS отдаёт 92.5.130.1 — переезд основного имени состоялся. Сертификат на месте, сайт работает. Здесь делать нечего.

officeplus.una.md пока ведёт на другую машину

Авторитетный сервер зоны ns2.una.md отвечает 93.115.136.18, а за этим NAT стоит внутренняя 192.168.0.148. Проверено сверкой страницы: она совпадает с .148 побайтово, а с новым хостингом — нет.

dig +trace officeplus.una.md A
officeplus.una.md.  600  IN  A  93.115.136.18
;; Received from 178.175.140.131#53(ns2.una.md)

Магазин там тот же самый — это не старый сайт, а второй работающий контур. Но это не новый хостинг.

Запись меняется не на nic.md

В присланной таблице зона officeplus.md. А officeplus.una.md — поддомен una.md, и его зону держат ваши собственные ns1.una.md / ns2.una.md (178.175.140.131 и 93.115.136.18). Записи, добавленные на nic.md, на это имя не повлияют.

На новом хостинге имя officeplus.una.md пока не настроено: по HTTP его подхватывает заглушка _, по HTTPS выходит редирект обратно на HTTP, а сертификат выписан только на officeplus.md и www.officeplus.md (до 5 ноября 2026). Поэтому одной правкой DNS не обойтись — нужны шаги 3 и 4.

Порядок работ

Порядок важен: сертификат нельзя выпустить, пока имя не показывает на сервер, а платежи нельзя переключать, пока сайт не открывается по новому адресу.

  1. Снизить TTL заранее

    зона una.md · ns1.una.md / ns2.una.md

    Сейчас TTL этой записи — 600 секунд, это уже удобно. За сутки до переезда поставить у записи officeplus.una.md TTL 300 секунд. Иначе старый адрес будет жить в кэшах провайдеров часами, и часть клиентов увидит старый сайт.

  2. Переключить A-запись

    зона una.md · ns1.una.md / ns2.una.md

    Имя в зонеТипБылоСтанет
    officeplusA93.115.136.1892.5.130.1

    После этого магазин на 192.168.0.148 перестанет быть доступен по этому адресу. Сам он продолжит работать — вопрос лишь в том, нужен ли он ещё.

    Проверка — адрес должен смениться:

    dig +short officeplus.una.md A

  3. Добавить имя в nginx

    92.5.130.1 · /etc/nginx/sites-enabled/officeplus

    В обоих блоках server дописать новое имя к server_name. Старое пока оставить — оно понадобится на шаге 5.

    server_name officeplus.una.md officeplus.md www.officeplus.md _;

sudo nginx -t && sudo systemctl reload nginx

  4. Выпустить сертификат

    92.5.130.1 · certbot

    Только после того, как шаг 2 разошёлся по DNS — Let's Encrypt проверяет домен обращением к серверу.

    sudo certbot --nginx -d officeplus.una.md \
     -d officeplus.md -d www.officeplus.md

sudo certbot certificates

  5. Решить, какое имя главное

    92.5.130.1 · nginx

    Оба имени ведут на одну машину, поэтому сайт откроется по обоим. Но поисковику и платёжному шлюзу нужен один канонический адрес. Если главным становится officeplus.una.md — со старого ставим редирект:

    server {
    listen 443 ssl;
    server_name officeplus.md www.officeplus.md;
    return 301 https://officeplus.una.md$request_uri;
}

    Одно исключение

    Путь /api/biro26/ редиректить нельзя: по нему Oracle 11g ходит простым HTTP и редиректы не понимает. Пока не сделан шаг 8 — оставить этот путь на старом домене рабочим.

  6. Переключить WordPress

    92.5.130.1 · база officeplus_wp

    Двух настроек мало: новый адрес нужно заменить и внутри контента — в ссылках, картинках, меню.

    sudo mysql officeplus_wp -e "UPDATE wp_options
  SET option_value='https://officeplus.una.md'
  WHERE option_name IN ('siteurl','home');"

# в содержимом страниц и настройках плагинов
sudo -u www-data wp search-replace \
  'https://officeplus.md' 'https://officeplus.una.md' \
  --path=/var/www/officeplus --all-tables --skip-columns=guid

  7. Переключить платежи

    Oracle · YBIRO_SETTINGS.NOTIFY_PUBLIC_BASE

    Из этой настройки строятся адреса возврата и подтверждения для MAIB и MIA. Сейчас там https://officeplus.md. Если её не сменить, клиент после оплаты вернётся на старый домен, а подтверждение платежа может не дойти.

    -- значение сейчас
SELECT SVAL FROM YBIRO_SETTINGS WHERE SKEY='NOTIFY_PUBLIC_BASE';

BEGIN y_ai_BIRO26.set_setting(
  'NOTIFY_PUBLIC_BASE', 'https://officeplus.una.md'); END;
/

    Отдельно предупредить MAIB

    Банк принимает возвраты только на адреса, зарегистрированные у него для мерчанта. Смена домена в настройке этого не делает — нужно письмо в MAIB, иначе оплата картой перестанет проходить. То же касается MIA.

  8. Пересобрать пакет Oracle

    Oracle · Y_AI_BIRO26

    Адрес зашит прямо в тексте пакета — в двух местах, строки 472 и 618 (gen_conturi и gen_conturi_pr). Через настройку он не меняется.

    v_url := 'http://officeplus.una.md/api/biro26/gen-docs-by-nr/'

    Править в sql/biro26/04_y_ai_biro26.sql и накатывать заново. Оставить именно http, не https: у Oracle 11g на этом сервере нет TLS-кошелька, а эндпоинт защищён ключом API.

  9. Обновить остальное

    приложение и внешние сервисы

    • Google Search Console — добавить новый ресурс и отправить смену адреса.
    • Шаблоны писем и подписи, если в них указан домен.
    • Соцсети, Google Business, визитки, бланки счетов.
    • Telegram- и WhatsApp-уведомления: ссылки на документы строятся из той же NOTIFY_PUBLIC_BASE — отдельной правки не требуют.

Проверка после переключения

  • dig +short officeplus.una.md → 92.5.130.1
  • Витрина открывается: https://officeplus.una.md/catalog → 200
  • Замок в браузере без предупреждений, сертификат на новое имя
  • Старый адрес ведёт на новый: curl -I https://officeplus.md/catalog → 301
  • Бэк-офис пускает: https://officeplus.una.md/login
  • Админка WordPress открывается и не уводит на старый домен
  • Пробная оплата картой проходит и возвращает на новый адрес
  • Счёт из ERP генерируется: y_ai_BIRO26.gen_conturi отдаёт файл, а не ошибку
  • Письмо клиенту приходит со ссылками на новый домен

Если что-то пошло не так

Откат — это возврат A-записи officeplus.una.md на 93.115.136.18 и NOTIFY_PUBLIC_BASE на старое значение. Всё остальное (nginx, сертификат, редирект) обратной силы не имеет: старый домен продолжает работать всё это время, поэтому магазин не падает.

Именно поэтому шаг 1 — низкий TTL. С TTL 300 откат разойдётся за пять минут, с «Auto» может занять сутки.

Почему не наоборот: перенести сайт на 93.115.136.18

Тот адрес — внешний шлюз офисной сети. За ним внутренние машины, и наружу проброшен только один порт. Боевой магазин там опубликовать нельзя без правки NAT на MikroTik и выпуска сертификата, а сам MikroTik не сохраняет конфигурацию автоматически — правила уже пропадали после сбоя питания. Держать магазин на 92.5.130.1 надёжнее.
