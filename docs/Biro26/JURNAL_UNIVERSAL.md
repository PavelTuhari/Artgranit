# Универсальный журнал документов (back-office «касса с кассиром»)

Одна форма на все документы — по модели, реализованной в LightAccounting
(`docs/UI_CONCEPT.md` §3). Открывается из хаба Biro26:
`/UNA.md/orasldev/biro26-journal` (нужна авторизация оператора).

**Никаких новых хранилищ.** Только существующие таблицы Oracle OfficePlus.

## Из чего состоит форма

| Блок | Содержимое |
|---|---|
| Полоса фильтров | период, поиск (номер / COD / клиент) + 4 кнопки: Актуализировать, Создать заказ, Клиент новый, Открыть |
| Шапка документа | список **Действий** и список **Печатных форм** — как в утверждённой модели |
| Мастер-грид | COD, дата, номер, клиент, сумма, строки, файлы, признак проводок; внизу «Документы: N · Сумма: X» |
| Четыре закладки | **Contări** · **Mărfuri** · **Fișiere** · **LOG** |
| Журнал выполнения | нижняя полоса: время, что запущено, ответ сервера, ошибки |

## Источники данных (существующие таблицы)

| Закладка / блок | Таблица Oracle |
|---|---|
| Мастер-грид | `TMDB_DOCS` (SYSFID 12280) + `VMDB_ST201M` + `TMS_UNIVERS` |
| Contări (проводки) | `VMDB_ST201D` / `VMDB_ST201M` (Дт/Кт, аналитика, сумма) |
| Mărfuri (первичка) | `VMDB_ST201D` + `TMS_UNIVERS` (код, артикул, UM, кол-во, цена, сумма) |
| Fișiere | `VMDB_DOCS_OLE` (прикреплённые PDF/HTML/XLSX) |
| LOG | `XLOG` (кто, когда, событие, станция) |
| Клиенты | `YBIRO_CLIENT` + `TMS_UNIVERS` |

## Регистрация клиента оператором

Кнопка «Client nou». Минимум — **денумире + тип** (физическое / юридическое
лицо); IDNO обязателен только для юрлиц (13 цифр), телефон/почта/адрес —
по желанию. Запись идёт **в те же таблицы, что и регистрация из кабинета на
сайте**: `y_ai_BIRO26.register_client` → `TMS_UNIVERS`, затем `YBIRO_CLIENT`.
Если e-mail не указан, ставится технический (`bo-<hex>@officeplus.local`) —
клиент существует в системе, а доступ в кабинет можно открыть позже.

## Заказ из back-office

«Creează comandă» → выбор покупателя (поиск по имени, телефону, IDNO, COD —
и по клиентам сайта, и по контрагентам ERP; тут же можно завести нового) →
подбор товаров из каталога с ценами → режим НДС → счёт. Используется **тот же
endpoint**, что и для заказов с сайта: `POST /api/biro26/shop/invoice` с
`client_cod` (разрешён для сессии оператора и для доверенного ключа).

## API

| Вызов | Назначение |
|---|---|
| `GET /api/biro26/journal/docs?from=&to=&q=&limit=` | грид документов |
| `GET /api/biro26/journal/doc/<cod>` | содержимое четырёх закладок |
| `GET /api/biro26/journal/clients?q=` | поиск покупателя |
| `POST /api/biro26/journal/client` | быстрая регистрация клиента |
| `POST /api/biro26/shop/invoice` | создание счёта на выбранного клиента |
| `POST /api/biro26/gen-docs-by-nr/<nr>?cod=&formats=` | действие «сгенерировать и прикрепить формуляры» |

Все API требуют сессию оператора (кроме последнего — он принимает и `api_key`,
т.к. его же дергает Oracle из `y_ai_BIRO26.gen_conturi_pr`).
