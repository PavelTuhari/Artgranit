1. Общие сведения

Система управления розничной продажей топлива в региональной сети АЗС.

ПараметрЗначение
Количество АЗС46
Виды топливаA92, A95, A98, Дизель
Способы оплатыналичные на кассе, MIA QR-код
Пересменок в сутки2–3 по графику
Режимы отпускасамообслуживание и отпуск сотрудником

Функциональность: приём цистерн, складской учёт по резервуарам, закрытие смены со сверкой, расчёт трёх независимых расхождений, бэк-офис по всей сети.

2. Ключевое решение: учёт по счётчику

Источником истины является тотализатор раздаточного пистолета (хранится в PECO_NOZZLES), а не сумма транзакций.

Обоснование: при учёте «по транзакциям» отпуск топлива, не попавший в систему, не оставляет следов вообще. При учёте по счётчику такой отпуск автоматически проявляется как расхождение — счётчик прокрутился, а оплаченных литров меньше.

Три независимых расхождения

liter_variance = meter_delta − txn_liters
                 -- топливо вышло, но не оплачено

cash_variance  = cash_declared − cash_expected
                 -- недостача/излишек ящика (MIA QR НЕ входит)

tank_variance  = dip_close − (volume_open + delivered − dispensed)
                 -- считается ОТДЕЛЬНО по каждому резервуару

Допуски

КонстантаЗначениеСмысл
TOLERANCE_LITERS0.5 лдопуск счётчик/транзакции
TOLERANCE_CASH1.0 (ед.)допуск кассы
TOLERANCE_TANK_LITERS50.0 лдопуск резервуара (каждый отдельно)

Превышение любого допуска переводит смену в DISPUTED и требует подтверждения PIN-кодом менеджера.

3. Модель данных

Префикс всех объектов — PECO_. Схема нормализована: 18 таблиц, 4 представления.

Справочники

  • PECO_REF_FUEL_GRADES — A92, A95, A98, DIESEL
  • PECO_REF_PAY_METHODS — CASH, MIA_QR
  • PECO_REF_SHIFT_STATUS — OPEN, CLOSING, CLOSED, DISPUTED
  • PECO_REF_TXN_STATUS — AUTHORIZED, DISPENSING, AWAITING_PAY, PAID, VOIDED

Мастер-данные

  • PECO_STATIONS — 46 станций
  • PECO_TANKS — резервуар на вид топлива на станцию
  • PECO_PUMPS — колонки, некоторые с самообслуживанием
  • PECO_NOZZLES — пистолеты; тотализатор хранится здесь
  • PECO_EMPLOYEES — сотрудники, роли ATTENDANT/MANAGER/ADMIN, PIN как PBKDF2-хеш
  • PECO_PRICES — версионные цены с VALID_FROM/VALID_TO

Операционные таблицы

  • PECO_SHIFTS — смены с расхождениями
  • PECO_SHIFT_METERS — показания по каждому пистолету за смену
  • PECO_TXN — продажи топлива
  • PECO_SHIFT_TANKS — снимок резервуара на смену (остаток, приход, замер, расхождение)
  • PECO_DELIVERIES + PECO_DELIVERY_ITEMS — приход цистерн
  • PECO_TANK_DIPS — ручные замеры уровня
  • PECO_EVENT_LOG — append-only журнал событий

4. Потоки и интерфейсы

Отпуск топлива (конечный автомат)

AUTHORIZED → DISPENSING → AWAITING_PAY → PAID
                  ↓             ↓
               VOIDED        VOIDED

Один конечный автомат обслуживает оба режима. Самообслуживание требует MIA-ссылку уже на авторизации. Отпуск сотрудником остаётся в AWAITING_PAY до оплаты на кассе.

Пересменка (цикл на смену)

  1. Оператор вводит закрывающие показания по каждому пистолету
  2. Система рассчитывает расхождения (литры, касса, резервуар)
  3. Оператор объявляет наличность в кассе
  4. При превышении допуска смена → DISPUTED, требует PIN менеджера
  5. Открывающие показания следующей смены = закрывающие предыдущей

5. Техническая реализация

  • Язык: Python 3.12, Flask
  • База данных: Oracle (одна схема на всю сеть, строки помечены STATION_ID)
  • Архитектура:
    • Бизнес-логика (расхождения, пересменка, PIN) — чистые функции в models/peco_shift.py, models/peco_txn.py, models/peco_inventory.py
    • Весь SQL — в models/peco_oracle_store.py
    • HTTP-маршруты и контроль доступа — в controllers/peco_controller.py и app.py
  • DDL: sql/100_peco_tables.sql … sql/104_peco_demo_data.sql
  • Развёртывание: python deploy_oracle_objects.py

Безопасность

  • PIN хранится как PBKDF2-HMAC-SHA256 с солью, 600 000 итераций
  • Все SQL через параметризованные запросы
  • Таблицы защищены составными FK по станциям
  • Уникальные индексы (функциональные и обычные) предотвращают гонку смен
