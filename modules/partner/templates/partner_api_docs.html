OfficePlus B2B API — Documentation

REST API for OfficePlus partners: catalog, prices, stock, incremental changes and order placement straight into the una.md ERP that powers officeplus.md. The contract mirrors the Ultra B2B API V1, so an integration written for Ultra ports with minimal changes (see compatibility).

Basics

Base URL: https://officeplus.md/api/v1

All requests and responses are JSON (Content-Type: application/json). All endpoints except the token ones require a valid access token.

Authentication

MethodPathPurpose
POST/auth/tokenobtain the token pair
POST/auth/refreshrotate tokens with a refresh token
POST/auth/revokerevoke all your tokens
curl -X POST https://officeplus.md/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username": "dealer@example.com", "password": "secret"}'
{
  "access_token": "…", "refresh_token": "…",
  "expires_in": 3600, "token_type": "Bearer",
  "user_email": "dealer@example.com", "user_id": 10
}

Send the access token as Authorization: Bearer <token> or X-API-Token: <token>. Access tokens live 1 hour; refresh tokens live 30 days and are rotated on every use.

Errors & limits

CodeMeaning
400validation error — body carries errors per field
401missing / expired / revoked token
403account disabled
404resource not found
429rate limit exceeded (120 requests / minute)
500server error
{"message": "Validation failed.", "errors": {"delivery": ["must be one of: pickup, delivery"]}}

Products

MethodPathPurpose
GET/productproduct list with filters
POST/product/batchproducts by codes (up to 1000)
GET/product/{id}one product by uuid or code

Query parameters

search, category, brand, min_price, max_price, sort (price_asc, price_desc, name_asc, name_desc), limit (1–1000, default 100), offset (default 0).

Product object

{
  "code": "GA82543",            // article (Ultra: ultra_code)
  "uuid": "225712",             // internal id (Ultra: ultra_uuid)
  "product_name": {"ro": "…", "ru": "…"},
  "description": "…",
  "description_by_language": {"ro": "…", "ru": "…"},
  "quantity": 12,
  "image_urls": ["https://officeplus.md/…"],
  "barcode": "4840010000029",
  "brand": {"name": "HP"},
  "category": {"name": {"ro": "Toner"}, "hierarchy": ["Cartus Toner", "Toner"]},
  "user_price": 80.0,           // YOUR price (per-partner price column)
  "fixed_price": 95.0,          // retail price
  "price_d": null, "promo_b2b": null
}

Batch

curl -X POST https://officeplus.md/api/v1/product/batch \
  -H 'Authorization: Bearer …' -H 'Content-Type: application/json' \
  -d '{"codes": ["225712", "GA82543"]}'

ultra_codes is accepted as an alias of codes for drop-in compatibility.

Categories

GET /category — the full group → category tree with product counts:

{"data": [{"name": {"ro": "Toner"}, "hierarchy": ["Cartus Toner", "Toner"],
           "level": 2, "products": 11}]}

Brands

GET /brand — {"data": [{"name": "HP", "products": 3425}]}

Quantity

GET /quantity (same filters as /product) and POST /quantity/batch ({"codes": […]}, up to 1000):

{"data": [{"code": "GA82543", "uuid": "225712",
           "product_name": {"ro": "…"}, "quantity": 12}]}

Changes

GET /changes?since=2026-08-28T00:00:00&entity=product&limit=1000

entity: product, price, quantity (omit for all). Response:

{
  "changes": [{"entity": "price", "action": "updated",
               "entity_id": "225712", "changed_at": "2026-08-28T09:00:00"}],
  "next_since": "2026-08-28T09:00:00",
  "has_more": false
}

Poll with next_since until has_more is false, then fetch the touched products via /product/batch.

Orders

POST /order — the order becomes a real web invoice in the una.md ERP. Prices are taken from your price column, never from the request.

{
  "delivery": "pickup",            // pickup | delivery
  "payment": "transfer",           // cash | transfer | card
  "products": [{"uuid": "225712", "quantity": 2},
               {"code": "GA82543", "quantity": 1}],
  "shipping_data": {"address": "…", "phone": "…"}   // optional
}
{"message": "Order created.", "order_id": 812345, "order_number": "  1234"}

Add "validate_only": true to check an order without creating it — the reply carries the computed total.

GET /order?limit=50 — your invoices: number, date, total, internal id.

Health

GET /health → {"status": "ok", "time": "…", "user_email": "…"}
