# AGENTS.md — правила для любого ИИ-агента в репозитории Artgranit

Читают Claude Code, Codex, Cursor и любой другой агент. Полная версия
инженерных правил — [`CLAUDE.md`](CLAUDE.md); git-концепция —
[`docs/GIT_WORKFLOW.md`](docs/GIT_WORKFLOW.md); ядро модулей —
[`docs/CORE_MODULES.md`](docs/CORE_MODULES.md).

## Перед первым действием

```bash
git branch --show-current && git worktree list && pwd
```

- Ты в `/Users/pt/Projects.AI/Artgranit` и ветка не `main`? Это чужой
  каталог с чужой веткой. **Не работать здесь.** Создай свой worktree:
  `python scripts/new_module.py <ключ> "<Название>"` (новый модуль) или
  `git worktree add ../Artgranit-<ключ> -b feat/<ключ> main` (любая задача).
- Ветка `main` в общем каталоге — только для `git pull --ff-only`, merge
  готовых веток и деплоя.

## Где лежит код задачи

| Что | Куда | Никогда |
|---|---|---|
| модуль | `modules/<ключ>/` (blueprint, routes, controller, store, rules, templates, sql, scripts, module.json) | `app.py`, `controllers/`, `models/`, `templates/`, `sql/` |
| логика для старого модуля | `models/<модуль>_<тема>.py`, вызов в одну строку | тело функции в общем файле |
| документация | `docs/<Модуль>/*.md` + `docs.json` | правка чужих `docs/` |
| тесты | `tests/test_<ключ>.py` с двумя тестами изоляции | — |
| DDL | `modules/<ключ>/sql/` + свой `scripts/<ключ>_deploy.py` | `deploy_oracle_objects.py` |

Проверка изоляции перед сдачей: `git diff --name-only main HEAD` — только
свои пути.

## Git: каждый шаг сохраняется

1. Hook коммитит и пушит каждый `Write`/`Edit` в репозиторий файла.
   Не полагайся только на него: после законченного шага —
   `git add <свои пути> && git commit -m "<ключ>: что сделано" && git push`.
2. Перед сдачей: `git log --oneline origin/$(git branch --show-current)..HEAD`
   должно быть пусто.
3. Общий файл (`app.py`, `CLAUDE.md`, `README.md`, старые шаблоны) — только
   точечный `Edit` после `git log --oneline -3 -- <файл>` и `git pull`.
   Полная перезапись общего файла запрещена.
4. Запрещено: `push --force`, `rebase` запушенного, `checkout`/`stash`/
   `restore` в общем каталоге, откат чужих коммитов, коммит чужих файлов.

## Чужие ветки и боевые площадки не затирать (правило №4)

Параллельные ветки и площадки (`192.168.0.250`, `92.5.130.1`) могут
содержать работу, которой нет в `main`.

1. Перед правкой файла на площадке — `md5sum` там против `md5 -q` локально.
   Различаются — качать их версию, править **поверх неё**, заливать с
   резервной копией `.bak-ГГГГММДД`.
2. Никакой перезаписи площадки целиком: ни `rsync --delete`, ни распаковки
   архива поверх каталога с более новыми файлами, ни `git checkout <ветка> -- путь`.
3. Новое — новым файлом (docs, скриншоты, стили, скрипты); в общий файл —
   только ссылка/вызов в одну строку точечным `Edit`.
4. Чужие ветки не сливать, не перебазировать, не откатывать.
5. Перед сдачей: `git diff --name-only main HEAD` — только свои пути.


## Ultra: цены и синхронизация (сайт биротики, ветка `feat/biro26-catalog`)

Модуль `modules/partner/` — мы как дилер Ultra по их B2B API. Всё, что ниже,
делается **только** его скриптами, штатным конвейером импорта и ничем другим.

| Шаг | Команда (из корня worktree, интерпретатор `Artgranit/venv/bin/python`) |
|---|---|
| каталог Ultra → буфер `BIRO26_GOODS` (SHEET='ULTRA') | `modules/partner/scripts/ultra_sync.py [--full]` |
| буфер → номенклатура + прайс (штатный `import_file`) | `modules/partner/scripts/ultra_publish.py --commit` |
| разбор без записи | то же без `--commit` (в `import_file` это честный DRY-RUN) |
| раз в час всё вместе | `modules/partner/scripts/ultra_cron.sh` (crontab: `17 * * * *`) |

**Правила, выстраданные 09.09.2026:**

- **Нельзя звать `YBIRO_Import_Marfa.import_all` напрямую.** Он читает всю
  таблицу без фильтра по источнику, его `assign_keys` выдаёт новый код каждой
  строке без ключа (так в июле родились ~22 000 дублей `GOG*`), а
  `import_prices` не закрывает старый период — на витрине будет две «текущих»
  цены. Только через `BIRO26PT_importData.import_file(p_src=>'ULTRA')`.
- **Мост к июльским карточкам `GOG*` — штрихкод**, а не артикул и не название.
  `ultra_publish.py` находит карточку по uuid картинки
  (`TMS_MPT_TVR.IE_LINKADRES` ↔ `photo_url` из API) и кладёт её штрихкод
  `4841…` в колонку `Barcode`; дальше приоритет 1 в `classify()` делает
  EXISTING сам. Своей логики сопоставления в скрипте нет и не должно быть.
- **Uuid товара (`GUID`) для моста не годится** — совпадает лишь в 1 704
  случаях из 22 267. Ключ — uuid *картинки*.
- **`CODVECHI` карточек `GOG*` не менять**: код стоит в адресах товара и в
  истории продаж. Артикул поставщика живёт в `TMS_MPT_IMPSRC.SRC_ARTICOL`.
- **Весь текст из API — через `cp1251_safe()`** (`models/biro26pt_loader.py`):
  база `CL8MSWIN1251`, иначе `ș ț ă â î` превращаются в `?` (6 813 названий
  в первой синхронизации).
- **Товар без категории получает группу `Ultra - diverse`** — без группы у
  него нет узла в дереве, и он невидим на витрине. `category.hierarchy[i]` —
  это `{code, name{ro,ru,en}, uuid}`: брать `["name"]`, иначе пусто.
- **Токен Ultra живёт час, полный обход дольше** — клиент перелогинивается
  сам и пишет блоками по 2 000; не «оптимизировать» это обратно в одну запись
  в конце.
- **Полный обход по `updated_at` теряет позиции** (26 186 из 37k за один
  проход): после `--full` дотягивать остаток адресно через
  `products_batch(ultra_codes)` — см. `PARTNER_API.md`.
- Рабочий период ERP перед `import_file` ставится на текущий месяц
  (`UN4PUBLIC.ENVUN4.EnvSetValue('PARAM_PERIODBEG'/'PARAM_PERIODEND')`) —
  иначе `ORA-20101`. Скрипт делает это сам.

## Язык: на чём писать что (владелец, 12.09.2026)

| Что пишется | Язык |
|---|---|
| **Общение с владельцем**, ответы в сессии, сообщения коммитов, рабочие заметки | **русский** |
| **Документация для заказчика** — книга-методичка `docs/SEOForge/GHID_*`, тексты на витрине, посты, инструкции для его людей | **только румынский** |
| Комментарии и сообщения кода БД (PL/SQL, SQL) | румынский + английский, `RO: … / EN: …` |
| Комментарии в коде приложения | русский (как сейчас) |

Уже написанное по-русски в документах заказчика **остаётся как есть** —
переписывать задним числом не нужно. Всё новое для заказчика — румынское.

Румынский пишется **с полной диакритикой** (`ș ț ă î â`): файлы в UTF-8,
и заказчик читает их как обычный текст. Исключение одно — тексты,
которые уходят **в базу учёта**: там кодировка CP1251, диакритики в ней
нет, и Oracle молча заменяет такие буквы на `?`. Подробности и проверка
перед записью — `docs/SEOForge/README.md`.

## Ссылки на созданные материалы — только полные

Владелец, 12.09.2026: относительные ссылки в переписке и в документах
бесполезны — по ним нельзя кликнуть и нельзя переслать коллеге.

**В ответах владельцу** каждый созданный материал называется ПОЛНЫМ адресом:

| Что создано | Как писать |
|---|---|
| документ в хабе | `https://officeplus.md/UNA.md/orasldev/b26docs/<Раздел>/<файл>` |
| страница бэк-офиса | `https://officeplus.md/UNA.md/orasldev/<адрес>` |
| страница магазина | `https://officeplus.md/<адрес>` |
| файл на диске | `/Users/pt/Projects.AI/<проект>/<путь>` — от корня, не от текущей папки |
| файл на сервере | `ubuntu@92.5.130.1:/home/ubuntu/artgranit/<путь>` |
| объект в базе | `OFFICEPLUS.<ИМЯ>` · `//orange.una.md:4024/cloudbd.world` |

**Внутри создаваемых документов** (инструкции, отчёты, md в `docs/`) — то же
самое: таблица «где что лежит» с полными адресами, кликабельными ссылками на
хаб и абсолютными путями к файлам.

Исключение одно: ссылки на файлы репозитория внутри самого репозитория
(`[CLAUDE.md](CLAUDE.md)`) остаются относительными — они работают на GitHub
и в редакторе.

## Сделано = в origin + в `main` + на площадке + проверено (правило №6)

TBControl, 02.09.2026: код восстановлен, протестирован, отчёт написан — и 47 дней
пролежал на ветке `claude/sweet-blackwell-5001c9`, не слитой в `main`; `/api/tbc/services`
всё это время отдавал 500. Поэтому:

1. **Первое действие сессии** — аудит: `git branch --no-merged origin/main`,
   ветки без upstream, `git worktree list`, `git status` в каждом worktree.
   Нашёл чужую незалитую/неслитую работу — не трогать, **сказать владельцу**.
   Свою — запушить сейчас же.
2. Шаг закончен → `commit` → `push`. Задача закончена → merge в `main`
   (`Artgranit-core`, `--no-ff`) → push `main` → выкатка → `curl`-проверка →
   `.md` с датой. Не выполнен хоть один пункт — в ответе владельцу так и пишется.
3. Hook коммитит локально и **не** гарантирует push; `claude/*`-ветки из
   `.claude/worktrees/` без push существуют только на этом Mac.
4. Чужой код: общие файлы — append/точечный `Edit` после `git log -3`;
   чужие ветки, worktree, файлы на площадках — не сливать, не удалять, не
   «чинить». На площадке файл может быть новее `main` (nufarul `app.py` =
   `prod/nufarul-live`): сверить `md5sum`, свою правку накладывать поверх их версии.
5. `app.py` на сервер — только после того, как все импортируемые модули уже
   лежат там и `py_compile` прошёл; откат из `.bak` при первом же 502.

## Живые ссылки, а не описания (правило №5)

Всё, что упомянул — давай полным адресом с `https://`, чтобы открывалось в
один клик; оба контура, если их два.

1. `https://officeplus.md/UNA.md/orasldev/crm/` — боевой,
   `https://nufarul.eminescu.md/UNA.md/orasldev/crm/` — тестовый (та же база).
   Внутренние (`192.168.0.250:8001`) — с пометкой «только через VPN93».
2. Якорь до нужного места: `…/GHID_CRM.html#comenzi`, `…/crm/#employees`.
3. Проверь, что ссылка живая (`curl -s -o /dev/null -w '%{http_code}'`;
   `302 → /login` для страниц под логином — нормально). Мёртвых не давать.
4. В документах и на плитках хаба — то же: полные адреса, а у каждой
   возможности ссылка на её раздел документации.
